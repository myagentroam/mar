# Workspace、文件或 Git 不可用

1. 确认 Workspace 真实路径位于 Node `allowedRoots` 下，且符号链接解析后也没有越界。
2. 用 Node 服务账号读取/写入目标目录；修正所有权、ACL 和挂载权限。
3. 对 Git 问题，在同一账号和目录执行只读 Git 检查，确认 `.git` 可访问。
4. 在控制台刷新当前 Workspace；路径移动后应重新登记而不是强行复用旧路径。

**成功标志：** 文件树、预览和 Git 状态恢复，且不会显示边界/权限拒绝提示。

不要把整个用户目录或磁盘加入 `allowedRoots` 来规避问题；应仅扩大到确实需要的父目录。

如果报错发生在重命名、移动或删除，先确认没有同名冲突、目标父目录可写，并在 Git 仓库中先检查未提交改动。修复后刷新文件树验证真实状态。
