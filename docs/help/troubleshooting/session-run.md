# 会话卡在 Working 或 Idle

1. 确认 Node 仍在线；浏览器或网络短暂重连不会自动终止 Node 上实际运行的任务。
2. 打开当前会话并等候状态/最终轮次同步；必要时刷新当前 Workspace 会话列表和历史。
3. `Working` 很久时查看最新工具卡和 Agent CLI 本机状态；确定不需要继续时点击停止，等待停止按钮禁用且状态回到 `Idle`。
4. 外部历史首次发送返回继续错误时不要重复提交；检查对应 Agent 的本机状态、服务账号登录态和工作区路径，确认无法继续时新建会话。
5. Compact 完成后等待上下文与最终会话状态同步，再继续发送。

MAR Agent 遇到历史图片文件缺失或无法读取时，会从模型上下文跳过该图片并保留文本继续执行，不会删除你的源文件。若当前任务仍需要该图片，请重新附加或让 Agent 再次读取源文件；无需因此新建会话。

**成功标志：** 会话与当前任务状态一致，队列按预期继续或保持暂停。

主动停止不会自动执行已排队消息；使用 `Ctrl+Enter` 的“停止后优先发送”才会停止当前任务并优先执行新消息。若 Agent CLI 本身异常，参阅[Agent 排障](../runners/runner-troubleshooting.md)。

不要通过连续刷新、重复点击停止或重复发送来“唤醒”会话。先等待状态明确变为 `Idle` 或显示失败，再根据 Agent 本机日志定位；额外操作只会增加消息队列干扰。
