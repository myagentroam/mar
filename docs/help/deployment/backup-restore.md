# 备份与恢复

备份必须按数据归属分别覆盖，不能只备份 Server。

| 数据                | 位置与备份要求                                                                                                                                                                            | 恢复后验证                             |
| ------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------- |
| Server 数据库       | 必须备份 MySQL 中的账户、登记、授权、模型与凭据、模板目录、企业配置和审计                                                                                                                 | 登录、资源与配置可读取                 |
| Server 持久文件     | 必须同时备份 `MAR_DATA_DIR`，包含运行票据签名密钥及技能缓存；Compose 默认对应企业部署目录的 `data/`                                                                                       | 配置与技能目录可用                     |
| Node 身份与索引     | 必须备份 Node 私有 JSON 和 `dataDirectory`，其中 `node-runtime.sqlite` 保存资源设置与托管索引                                                                                             | 原 Node 身份与工作区正常               |
| 模板和托管对话      | 使用托管功能时，必须备份 `dataDirectory` 内 `conversationHosting.storeDirectory` 指定的整个目录（默认 `hosted-conversations`），包含发布模板、对话历史、上传及输出文件；不能只复制 SQLite | 已有对话、附件、输出和已发布模板可读取 |
| 普通 MAR Agent 历史 | 使用 MAR Agent 时，备份 Node 服务账号的 `~/.mar/agent/`，保留会话及相关生成文件；这不能替代托管目录备份                                                                                   | 普通会话历史与相关文件可读取           |
| 工作区与其他 Agent  | 按需备份源码、Git、业务数据、已安装技能，以及其他 Agent 官方规定的配置和历史；另行保护部署账号的仓库凭据                                                                                  | 文件、Git、技能与 Agent 登录可用       |

实际路径以服务账号、Node 私有配置和 Compose 挂载为准，见[端口与数据位置](../reference/ports-paths-data.md)。日志不等于备份。正在执行的进程和终端不能从备份继续；普通 Workspace 的 MAR Agent 正常退出交接有条件地恢复未完成任务、Goal 和队列，见[会话恢复](../workbench/sessions.md#正常停止后的自动续作)，但不能假定任意备份或异常退出都能恢复这些运行状态。

## 备份前

1. 选择维护窗口，停止 Node、Server 及其他业务写入。逻辑备份时保持 MySQL 运行，使用数据库备份工具导出，再备份持久目录；如采用冷备份，先正常关闭 MySQL，再按所选备份工具要求复制数据。数据库和文件应属于同一维护窗口，不要直接复制运行中的数据库文件。
2. 一并记录 Server/Web 产品版本、Node 公共组件版本、配置路径、挂载位置与服务账号权限，避免将数据库和文件恢复到不匹配的版本。
3. 对备份加密并限制访问，在隔离环境演练后才将其视为可恢复备份。

## 恢复步骤

**先保留未经启动的完整备份副本。** 托管 Node 启动恢复完成后会立即执行一次非活跃对话清理，之后每 24 小时执行；默认阈值为 60 天。旧备份中的对话可能在首次启动时就达到清理条件。先离线核对 `conversationHosting.inactiveRetentionDays`、备份时间与数据保留要求，只在可丢弃的隔离副本上启动演练，不要直接启动唯一的备份副本。

1. 停止相关服务，将同一备份集的数据库、持久目录和配置恢复到隔离环境，先使用与备份匹配的应用版本。
2. 确认恢复副本不会连接生产 Server；不要同时启动两个使用相同 Node 身份的实例。无法保证身份连续性时，按[接入 Node](../getting-started/connect-node.md)登记替代节点，并重新核对资源关系。
3. 启动 Server，确认健康与账户可登录；再逐台启动 Node，检查工作区路径和服务账号权限。
4. 读取普通会话与文件；使用托管功能时，还要打开已有对话、读取上传与输出、从已发布模板创建测试对话，并执行一次只读请求。
5. 确认功能正常后再切换正式服务。不要假定中断的任务已成功完成或任意备份都包含正常退出交接；先核对会话状态再决定是否继续。

**成功标志：** 资源登记与 Agent 对话历史可读取，新的任务和终端可创建。

安全提示：备份通常含密钥或源码，必须加密、限制访问并演练恢复。
