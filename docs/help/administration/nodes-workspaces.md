# 管理 Node 与 Workspace

节点与工作区管理列表每页读取 20 条，服务端先按管理权限、筛选条件和排序确定结果再分页。工作模式资源树和资源选择器仍读取完整授权范围，不由管理列表的当前页决定。

Node 独立安装并注册到 Server，按个人或组织资源的标准权限管理。Server 不会自动创建或运行 Node。

## 前置条件

只要资源对当前用户可见，就可以查看 Node/Workspace 详情；登记工作区和工作区分组需要同一 Node 的登记工作区权限；移除工作区要求该 Workspace 的管理权限，只有 Node 使用授权不能移除。重命名和密钥配置仍需要各自的管理权限。企业版中，个人资源和组织资源的管理范围不同；管理员不因角色自动获得任意 Node 的宿主机登录权限。

## 管理步骤

在“工作”资源树中，节点和工作区的“更多”菜单均提供“上移 / 下移”；工作区只在同一分组内调整，未分组工作区之间也可调整。桌面端还可拖动节点名称或同组工作区排序；落点行的上边线或下边线表示插入到目标上方或下方。首尾禁用对应操作，筛选期间禁用排序。排序不要求资源管理权限，不改变当前工作区、顶部标签或分组，只保存在当前浏览器标签页，刷新后恢复，不同步到账号、组织或其他设备。

1. 打开“管理 → 节点管理”，点击“注册节点”，填写名称和归属后创建注册密钥，供一台目标主机首次注册。创建成功会关闭表单并打开独立确认弹窗，展示注册密钥、使用说明和部署指引；关闭前请复制并保存注册密钥，再按照部署说明在目标设备上完成节点注册。每个密钥只能使用一次，节点连接成功后会显示在列表中。
2. 工作区分组在“工作”资源树中操作，不在“管理 → 工作区管理”中编辑。具备登记工作区同一节点权限的用户，可在工作区“更多”菜单中使用“移动到分组”：选择当前节点已加载的已有分组，或直接输入新分组；留空保存会把工作区移出分组。也可把工作区拖到分组标题以直接迁入，拖到未分组工作区或所属 Node 行以移出分组，即使没有未分组工作区也可操作；不支持拖到其他 Node。同组内拖动只调整当前浏览器中的显示顺序。资源树按“Node → 工作区分组 → 工作区”展示：有名称的工作区分组按名称优先显示并可展开，未分组工作区随后直接显示在 Node 下。树中的筛选框只筛选当前已加载的节点名称、工作区分组、工作区名称和路径；命中节点时不会连带显示不匹配的工作区，不会扩大可见资源或请求额外资源。
3. 打开节点详情确认平台、Node/Server 版本、在线状态、“支持 Agent”和升级状态。已配置 Supervisor 且 Node 低于 npm 中不超过当前 Server 版本的最高稳定版本时，可确认影响后逐台“推送升级”。节点列表上的“推送全部”经确认后向当前管理范围内所有在线、可升级的节点逐台发送请求，不受当前筛选或分页限制；不可升级节点不会收到请求，部分失败会显示失败节点与原因。等待活动 Run 期间可取消，进入安装后等待 Node 自动重连。
4. 在“工作”模式的 Node → Workspace 资源树中，通过节点行的“更多”菜单查看详情或登记工作区；登记成功后新工作区会自动打开并成为当前工作区。通过工作区行的“更多”菜单查看详情、移动到分组、重命名或移除工作区。顶级菜单改名不改变这些功能；详情始终可查看，登记和分组使用登记工作区同一节点权限，移除使用该 Workspace 的管理权限，其他操作仍按各自权限可用。
5. 社区版的 Admin 可对自有且支持该能力的在线 Linux Node，在节点详情“托管对话”字段内启用或禁用托管对话。企业版共享托管要求 Node 归属组织；企业状态中的个人 Node 不显示启用按钮。此前已启用的存量个人 Node 仍保留禁用入口。Node 会持久化私有配置并立即初始化，无需手工编辑配置或重启。禁用会保留托管目录、SQLite 索引和会话历史；活动或启动中的托管 Run 会使 Node 拒绝禁用，不会自动取消用户对话。未启用时页面不显示“对话存储维护”区域；启用后显示托管目录占用、所在文件系统的使用率与可用空间，探测失败时仍保留维护区域和已启用状态，并显示 Node 上报的不可用原因。使用率达到 85% 显示高水位；达到 95% 后只禁止新建托管对话，已有对话仍可打开、运行、上传、导出或删除。
6. 具备 Node 管理权限时，可在节点详情开启 Computer Use。开关默认关闭；开启后先显示“初始化中”，Node 会从 npm 下载并校验固定精确版本的当前平台受管 Python/PyAutoGUI Runtime，再安装到 Node 私有目录；不会调用 pip，也不会使用系统或 Workspace Python。当前首版仅支持 Windows x64 与 Linux x64，其他平台会明确显示暂不支持；包未发布、下载失败或损坏也会显示不可用，但不影响 Node 与其他 Agent。关闭并重新打开详情，或使用现有刷新按钮，可查看 GUI 是否可用及失败原因。Windows 必须运行在当前交互用户桌面；Linux 仅支持可靠输入注入的 X11，Wayland 不会显示为可用。探测只检查截图和当前平台的权限／后端证据，不会试探点击、输入、粘贴、读取或改写剪贴板内容。仅截图成功不代表可控制桌面；输入权限、剪贴板后端不可用或缺少证据时仍会显示不可用。Linux 需要可用的 XTEST 扩展及 xclip 或 xsel 剪贴板后端。关闭开关会释放 Computer Use 资源，但不会停止无关 Agent Run。
7. 清理前选择 1–365 天非活跃阈值并先预览候选数量与预计释放空间，再确认永久清理。执行时 Node 会重新筛选并跳过正在运行、结算、Watch、上传或永久删除搬迁中的对话；预览不是待删除清单。默认自动清理阈值为 60 天，每 24 小时运行一次。用户确认删除对话后会立即永久删除，不保留恢复期。
8. 需要移除时先停止活跃 Agent、关闭终端，再删除 Node 登记。

**成功标志：** 资源树与节点详情一致，授权用户能打开其被允许的 Workspace。

节点管理只推送升级意图，安装由宿主机已配置的 Supervisor 执行。页面不会创建 Linux systemd、Windows 计划任务或 macOS LaunchAgent，也不会远程提权；首次启用必须先按[安装与注册 Node](../deployment/node-installation.md)完成平台自启动。完整状态与失败处理见[升级 MyAgentRoam](../deployment/upgrade.md)。

系统管理员可在相互独立的“节点管理”和“工作区管理”中查看并管理全部用户资源，包括其他用户的个人 Node/Workspace。个人资源仍不可修改归属或授权；管理操作也不会让管理员在业务工作台使用该资源的 Workspace、Agent、文件或终端。

具备 Node 管理权限时，节点详情和其 Workspace 详情都可以配置该 Node 的环境密钥；两处操作的是同一组节点密钥。只有 Workspace 管理权限时不会显示该入口，也不会获得 Node 密钥权限。

删除 Node/Workspace 只删除 Server 登记和关系，不删除宿主机文件；离线 Node 不等于已禁用，先看错误和心跳时间。下一步：[Node 注册失败或离线](../troubleshooting/node-offline.md)。

## 常见失败

- 注册后同名 Node 不出现：注册密钥只能使用一次，检查目标主机日志和登记时填写的显示名称。
- Workspace 无法共享：个人资源不可共享；先确认其归属及当前 License/角色。
- 删除受限：冻结态或正在运行的资源会限制管理写操作，先处理运行状态或恢复 License。
