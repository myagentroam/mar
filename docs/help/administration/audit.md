# 查询与导出操作审计

企业版审计记录管理与认证操作，以及组织共享会话已接受的用户输入，帮助定位谁在何时对哪些资源执行了受审计动作。

## 前置条件

需要审计查询权限；ADMIN 可查全量，ORG_ADMIN 只查子树，MEMBER 没有入口。先确定排查时间范围和资源范围，避免导出无关记录。

## 步骤

1. 在“管理 → 操作审计”按时间、事件类型、结果或资源筛选。
   桌面端按页浏览；移动端滚动接近列表底部时自动追加，加载失败可在原位重试。
2. 打开单条记录查看操作人、目标、结果和系统允许展示的关联信息。组织共享 Node 的普通会话输入只会在获权详情中按需显示为纯文本消息。
3. 需要留档时按当前权限导出 CSV，并在受控位置保存。

**成功标志：** 查询结果仅覆盖你的授权范围，导出内容与筛选条件相符。

审计记录组织资源的写入、控制与执行，包括配置、授权、普通 Workspace 会话控制、文件/Git 变更及可写终端打开；一次终端打开只记录一条事件，授权、接入和关闭阶段不单独记录。普通组织 Workspace 首条及后续已接受的用户输入，只在获权详情中显示。读取、预览、下载、导出、Watch 和心跳不审计；托管对话和个人内部资源操作不审计。个人注册、注销、撤销等影响 Server 登记或身份信任关系的操作仍保留。

列表和详情统一使用“业务: 操作”，例如 `Node: 重命名`、`Session: 发送消息`，时间按本地时区采用 24 小时制。详情中的操作人、目标及可命名的组织、Node、Workspace、Session 和授权对象显示为“名称 / ID”；无名称则保留原 ID，不用当前名称冒充历史快照。请求、操作、Run 和 QueueItem 等技术 ID 仍可用于关联排障。

每条记录同时保留结构化关联信息、用户友好的目标名称快照及安全的变更前后值，不再用 HTTP path 表示业务动作。审计异步尽力记录：故障、满载、断线或重启可能丢失事件，但不会等待、拒绝、回滚正常操作，也不会补采。Agent 回复、文件/终端正文、密码、Cookie、OAuth token 和密钥不会记录。

消息正文不会出现在列表、默认 CSV、浏览器持久化、日志或 metadata 中。只有 ADMIN 或管理目标组织子树的 ORG_ADMIN 可以在单条详情读取；MEMBER 没有审计入口。默认保留 180 天；管理员可在系统配置设为 1–3650 天。

导出 CSV 时系统会处理中和电子表格公式前缀，但仍应在受控工具中打开，避免再次转发到不受信任位置。
