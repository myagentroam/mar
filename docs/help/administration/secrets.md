# 管理环境密钥

密钥主列表每页向服务端读取 20 条，搜索覆盖完整管理范围。节点或工作区详情中的密钥配置是完整目标快照，全部展示，不分页。

环境密钥用于集中管理 Agent 或终端所需的 API Key、Token 等敏感信息，并在新建运行和终端时通过环境变量注入。

## 前置条件

你对目标作用域有环境密钥管理权限；准备好环境变量名和密钥值，并确认该值确实应由 Agent/终端进程读取。不要用环境变量替代用户密码或长期交互登录流程。

## 步骤

1. 在“管理 → 环境密钥”管理个人环境密钥；企业版 `ADMIN` 或 `ORG_ADMIN` 还可选择授权范围内的组织并管理组织环境密钥；在 Node 详情中管理节点环境密钥，在 Workspace 详情中管理独立工作区环境密钥。
2. 新增或更新环境变量名和密钥值，名称使用合法环境变量格式；值会向有权管理该作用域的用户回显。
3. 确认同名覆盖：个人优先于工作区，工作区优先于节点，节点优先于离 Node 最近的有效组织祖先。组织环境密钥默认仅本组织生效，明确设为公开后才向子孙组织继承。
4. 新建 Agent 会话运行或终端，验证目标程序读取到预期值。

**成功标志：** 新建运行/终端使用更新后的值；已存在的运行和终端保持其创建时快照。

Workspace 环境密钥需要该工作区的管理权限，不要求或授予 Node 密钥管理权限；仅有工作区使用权不能查看或修改密钥值。注销工作区会删除其密钥。工作区密钥不注入节点级终端或托管对话。

删除环境密钥会影响之后新建的运行/终端，不会回收已注入的进程环境。不要用名称相同但不同用途的密钥制造歧义。安全边界见[环境密钥与注入顺序](../concepts/secrets.md)。

## 常见失败

- 新运行没读到值：确认创建时间晚于更新、名称大小写一致，并检查更高优先级作用域是否覆盖。
- 无法保存：检查管理权限、冻结态与变量名格式提示。
- 值出现在日志：立即撤销/轮换该环境密钥，清理公开日志，并检查调用命令是否主动回显环境。
