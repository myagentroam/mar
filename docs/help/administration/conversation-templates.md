# 管理对话模板

模板管理列表每页向服务端读取 20 条；排序覆盖完整列表，不仅当前页。用于创建对话的模板选择器仍展示全部可用模板。

对话模板把来源 Workspace 的完整安全目录树发布为新建对话使用的不可变快照，并定义允许模型、MCP、网络模式、对话总存储和单文件上传上限。模板草稿保存在 Server，发布版本的目录清单、文件与受控符号链接、manifest 和 MCP 配置快照由所选托管 Linux Node 保存。

## 版本适用范围

社区版的固定 Admin 可在自有个人 Linux Node 上创建、测试和发布模板，并使用托管对话，不需要企业 License 或组织授权。企业状态的共享模板要求组织 Node；下文的组织归属和授权步骤只适用于企业状态。两种授权状态均须先在[节点详情](nodes-workspaces.md)启用托管能力并确认可用。

## 前置条件

- 当前账号具备模板管理权限；企业状态中的模板授权需要企业管理员权限。
- 至少一台在线、未禁用的 Linux Node 支持对话托管，来源 Workspace 已登记并可读取。企业状态要求该 Node 归属组织，不允许个人 Node 承载共享模板；社区版使用 Admin 自有的个人 Node。
- 来源 Workspace 根不能已有 `inbox/` 或 `output/`，这两个名称保留给每个对话的可写目录。

## 创建、预检与发布

1. 打开“管理 → 对话模板”，选择“新建模板”。
2. 选择来源 Node 和 Workspace，填写名称与说明。系统会发布整个 Workspace，不需要配置包含路径。模板创建后来源固定；如需使用其他 Node 或 Workspace，请新建模板。来源目录建议按[维护对话模板 Workspace](template-workspace-maintenance.md)分离维护文档与实际模板指令。
3. 选择允许模型和默认模型。候选只来自来源 Node 所有者当前获得的有效模型授权；同名或同一上游模型的多个配置会分别显示，可独立选择。模板只保存所选配置 ID 和当前名称快照，不另存上游模型 ID、连接参数或凭据；运行时从当前获权配置加载这些信息。编辑时，已不可见的配置会自动移除，默认配置会回退到剩余第一项；没有任何可用配置时不能保存、测试或发布。系统不会按名称或上游模型自动替换失效引用；若旧模板选择失效，请重新选择配置、保存并发布。思考强度使用模型默认，模板不配置工具、Skill 或模型输出上限。
4. 从来源 Workspace 当前有效 MCP 配置中多选需要随版本发布的 MCP。列表为空时不能手工输入 ID；Skill 会从镜像中的 `.agents/skills/` 自动发现，不在模板页面选择或展示。
5. 选择网络模式：
   - **无网络：** 本地进程不能联网，Web 工具、模型 Hosted Web 和远程 HTTP MCP 都不可用；仍可离线使用受沙箱约束的本地 stdio MCP。
   - **不受限：** 允许沙箱进程、Node 本地 Web Fetch、可用的 Web Search、模型 Hosted Web 和已选择的远程 HTTP MCP 访问 Node 可达网络；文件与进程隔离仍保持不变。
6. 以 MiB 设置对话总存储和单文件上传上限，然后保存草稿。
7. 编辑已有草稿时选择“测试草稿”。该操作检查完整 Workspace、安全排除、保留目录、文件类型、符号链接、模型、MCP、网络和配额，不会创建测试对话、Agent 会话或持久目录。
8. 选择“发布”并确认当前配置。页面会等待本次发布结果；成功后生成下一个递增的发布版本，例如 `1`、`2`、`3`。只有成功发布才增加版本号，单独编辑或保存配置不会增加。每个版本都包含目录清单、文件与链接清单、逐文件 hash、整体内容 hash 和 MCP 配置 hash，之后修改 Workspace、MCP 配置或草稿都不会改变已发布版本。

发布会排除根 `README.md` 和根 `AGENTS.md`，并把可选的根 `AGENTS.template.md` 作为发布版本的 `AGENTS.md`；该模板指令必须是普通文件。系统还会自动排除 `.git`、`.mar`、`.env*`、凭据和明确密钥文件等敏感内容；`node_modules`、`.venv`、普通依赖与隐藏工作流资源会随完整快照发布。普通文件和空目录会保留；符号链接只允许解析到同一快照内，或解析到沙箱固定只读提供的 `/usr`、`/bin`、`/sbin`、`/lib`、`/lib64` 运行时目录。断链、循环链接、越界链接、指向被排除内容的链接及 socket、设备、命名管道等特殊文件会使发布失败。处理页面报告的来源、`inbox/output` 冲突、MCP、链接、容量、文件变化或 Node 中断问题后再重新发布。如果等待达到页面上限，发布仍可能继续；稍后刷新列表或详情，确认发布版本是否增加。

## 发布版本、模板状态与授权

- “详情”显示当前发布版本和按版本号倒序排列的发布记录。每条记录包含发布版本、文件数、按 `B/KB/MB/GB` 显示的大小和发布时间；页面不展示内部发布任务或版本内部状态。
- “停用版本”阻止新对话和后续自动升级选择该版本；已绑定该版本的已有对话继续保留。
- 每个版本只保存一份独立 Workspace 快照；对话运行时共享只读挂载，不会为每个对话复制模板文件。
- 发布新版本不会立即改写已有对话。每次新 Run 开始前，Node 查询并完整校验当时最新的可用版本，以该版本启动 Run；只有 Run 成功启动且消息被接受后才原子切换。升级失败时当前发送失败，但旧版本、历史和可写文件保持不变，下一次发送会再次查询并重试。
- “归档”停止模板后续使用；“删除”立即从新建目录移除模板，但不会删除已有对话中的名称快照和最后已生效版本。
- 企业状态中的“授权”只选择组织，且目标必须是承载 Node 所属组织或其下级组织。选择根组织即对企业内所有用户公共可用，不需要另选“整个企业”；不支持按单个用户授权。没有有效组织授权的用户不会在“对话”入口看到该模板；有效模板授权已足够让用户创建、查看和继续自己的托管对话，但不会授予承载 Node、源 Workspace、普通文件或终端权限。

**成功标志：** 模板显示为“已发布”，有权用户可在主菜单“对话”中看到并显式选择它。
