# 社区版、企业 License 与冻结态

新部署默认为社区版：固定 `admin` 可使用，登记 Node 数量不受限制。导入绑定本机的有效企业 License 后才出现组织、RBAC、共享、SSO 与审计管理能力。

社区版固定管理员也可在“管理 → 系统配置”管理部署设置，无需企业 License。配置审计留存天数不授予审计查询或导出权限；企业冻结状态仍禁止修改系统配置。

## 前置条件

由授权方提供与当前 Server 主机匹配的 License。申请码只用于签发/校验，不应视为可公开的部署诊断信息。

## 步骤

1. 以系统管理员打开“管理 → 系统信息”，在“License 授权”中复制申请码并交给授权方签发，不要公开完整环境或主机信息。
2. 将授权方返回的完整 License 文档粘贴到输入区，点击“导入 License”，检查企业名称和到期状态。
3. 状态有效后再创建组织、用户和共享资源。

**成功标志：** License 页显示有效企业状态，相关管理入口可写。

到期或失效进入冻结态：现有登录、Node 重连、已登记 Workspace、Agent、文件、Git 和终端继续可用，但用户/组织/共享/SSO/注册等管理写操作受限。导入有效 License 即可恢复。

导入失败时核对主机、授权状态与文件完整性；不要通过修改数据库或系统时间绕过校验。

正式部署使用同一套程序和镜像，激活不需要替换安装包。正式部署的两种授权状态都必须提供真实主机 UUID；容器必须只读挂载宿主 UUID 文件，缺失或无效时不能启动。仅供本机体验的 [npm 快速开始](../getting-started/npm-quick-start.md)固定为社区能力，无需 UUID，也不支持激活；系统信息不生成申请码或显示 License 导入操作。社区基础功能与企业功能的区别由 License 决定，不影响个人资源与组织资源的权限隔离。

## 为什么正式部署的社区版也需要主机 UUID？

正式部署的社区与企业使用相同的 Server 启动和主机身份机制。Server 在本地从真实 UUID 派生主机指纹，企业 License 校验使用它绑定 Server 主机。社区版不需要申请企业激活，也不依赖在线 License 校验服务。

该主机身份检查不是分析数据上传。License 在本地校验；申请企业激活时，由管理员主动将包含主机指纹的申请码交给授权方，请勿公开申请码。这不意味着整个产品离线：模型 Provider、配置的集成与其他网络功能有各自的数据流。

容器必须只读挂载真实宿主 UUID；虚拟机也须暴露有效 UUID。缺失或无效时拒绝启动，不回退为随机生成的身份。将 Server 迁移至 UUID 不同的主机时，企业 License 需重新签发并绑定新主机；社区版仍要求新主机的有效 UUID，但无需企业激活。社区版为单用户使用，不限制登记 Node 数量。
