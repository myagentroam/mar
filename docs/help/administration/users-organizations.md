# 管理用户、组织与角色

用户列表按每页 20 条向服务端读取；筛选和排序覆盖当前权限范围的全部用户。组织树是完整的层级配置，直接全部展示，不分页。

该功能需要有效企业 License。社区版仍可使用固定管理员和个人资源。

## 前置条件

License 状态有效，且你是拥有企业或组织子树管理权限的用户。先确定资源该属于个人还是组织；两者不能通过普通共享强制互转。

## 步骤

1. 在“管理”创建组织树，再创建用户并分配到一个组织。
2. 为用户选择“成员”“组织管理员”或“系统管理员”；角色决定可管理范围。系统管理员固定属于根组织。
3. 将 Node/Workspace 归属到个人或组织；仅组织资源可以共享。
4. 使用授权入口向用户、组织或企业开放所需组织资源。

**成功标志：** 目标用户登录后只看到自己个人资源和被授权资源。

系统管理员可在用户列表点击固定 `admin` 的“编辑”，修改显示名称和邮箱，不会中断其已有工作台或终端连接。用户名、系统管理员角色及根组织归属不可修改；该账号仍受不可删除、禁用、降级或取消本地密码的恢复保护，管理页不提供密码重置。修改其密码请使用该账号的账户安全入口。

不能删除根组织；删除用户/资源登记不会删除 Node 主机文件。冻结态禁止管理写操作，恢复有效 License 后再修改。下一步：[社区版、企业 License 与冻结态](license.md)。

## 常见失败

- 看不到用户或组织：你的角色仅覆盖当前组织子树。
- 授权后仍不可访问：刷新目标用户的资源树，确认 Node 与 Workspace 的组织关系合法且授权未被撤销。
- 删除组织失败：先处理子组织、成员、资源和 SSO 引用；界面会在删除确认中说明受影响对象，不要假定资源会自动转移。
