# 环境密钥与注入顺序

环境密钥是通过环境变量传入 Agent 和终端的 API Key、Token 等敏感信息。新建 Agent 运行或终端时，系统会把已授权的密钥值注入相应本机环境。相同名称按**个人、工作区、节点、最近有效组织祖先**顺序覆盖，排在前面的作用域优先。

| 作用域 | 适合保存                                           | 管理入口       |
| ------ | -------------------------------------------------- | -------------- |
| 个人   | 仅自己使用的 API Key                               | 环境密钥       |
| 工作区 | 仅应出现在指定 Workspace 的项目配置                | Workspace 详情 |
| 节点   | 只应出现在某台 Node 的值                           | Node 详情      |
| 组织   | 企业版组织共享的值；可设为仅本组织或向子孙组织公开 | 环境密钥       |

组织环境密钥沿 Node 所属组织的祖先链由远及近合并，离 Node 最近的有效组织值覆盖更远祖先；节点值再覆盖组织值，目标工作区值覆盖节点值，个人值最终覆盖工作区值。社区版没有组织环境密钥。

工作区环境密钥只应用于该 Workspace 的运行、定时执行、MCP 配置和工作区级终端，不应用于同节点其他工作区、节点级终端或托管对话。仅具备该工作区管理权限的用户可查看和修改其值；工作区使用权不等于密钥管理权。注销 Workspace 会删除其环境密钥。

环境密钥在新建运行和新开终端时取快照；已运行的 Agent 或已打开终端不会因之后编辑而改变。界面向有权管理作用域的用户显示值，但不会把它写入浏览器持久缓存。

安全提示：环境密钥的目标是避免把值写进 Agent 消息和 Git；终端中的进程仍可能读取环境变量。只授予必要作用域，避免在命令输出、截图或提交记录中回显。
