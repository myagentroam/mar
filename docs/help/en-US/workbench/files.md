# Browse, Search, and Manage Files

Files shows the selected Workspace as a lazily loaded tree. Files and folders are clickable, and more actions appear when you hover over a row.

## Prerequisites

The Workspace must be online and readable. Creating, renaming, moving, or deleting also requires file-system permission for the Node service account and run access to the resource.

## Steps

1. Select **Files**, expand a folder, and select a file. Text, Diff, images, PDF, Office, video, and audio open in one file-tab strip; every tab shows its file name with a full-path tooltip, while its content page keeps independent state. The × in a tab closes that file only. **Close file window** in the upper-right corner closes all file tabs and returns to the workbench, or closes the browser window in a companion file window. Unsaved edits require confirmation first; canceling any confirmation keeps all tabs open. `Ctrl+W` / `Alt+W` closes the active file tab; `Esc` / `Ctrl+Shift+W` / `Alt+Shift+W` closes the whole file window. Esc first dismisses the topmost find panel, menu, or settings dialog. Mobile browser Back also closes the whole window; canceling an unsaved-change confirmation keeps it open. Companion file pages and tab-free rendered previews use the same behavior. Ctrl combinations require the browser to deliver the key event; use Alt as an alternative. Additional entries load automatically near the bottom of an expanded directory; retry in place if loading fails. Use **Filter displayed items** to filter currently loaded files and folders by name or relative path; clear it to restore the tree. Filtering does not read folders that have not been expanded.
2. Use the **All**, **Workspace**, **Session**, **File**, and **Symbol** tabs in Quick Open. Workspaces match display names only, not paths or Node names; Sessions match the titles of loaded sessions in the current Workspace. All results are ranked by match strength first, with ties ordered as Workspace, Session, File, then Symbol; definitions precede references when Symbol scores tie. Enter a complete name to find a symbol: definitions can appear before references finish loading. Selecting a Session opens it in the current Workspace. Selecting a symbol or file immediately opens its preview without switching the Aside tool. The file tree expands its ancestors and selects the target in the background, then reveals it when Files is shown. Selecting a Workspace switches to or opens its tab. For duplicate file names, add space-separated terms to match the relative path, such as `app src` for `src/app.ts`; term order does not matter. You can enter `foo.ts:12` for a root-level file to jump to a line. The current Workspace's path index is built on demand; the first use may show “Preparing the index”. Each result type shows its own progress, failure, or timeout. If results are incomplete, refine the query; failure details and Retry are available. **Search** finds file contents and can open the matching line. It searches plain text by default; select **Use Regular Expression** above the search box before running a pattern search. Invalid patterns show an error.
3. Long file and folder names are abbreviated in the tree. Hover a row to see its complete relative path. The open file remains selected in the tree.
4. Hover over a row and select `…`. A file can be downloaded, copied as a relative or absolute path, renamed, or deleted. A folder also supports creating files or folders and uploading files. **Copy absolute path** copies the full path on the Node host; for the root, it copies the actual Workspace root path. This action is unavailable until the root path is known. When an authenticated loopback direct connection confirms that the browser and current Node are on the same device, **Open in local file manager** also appears. Windows opens a folder or selects a file, macOS opens a folder or reveals a file in Finder, and Linux opens the containing folder for a file. The Node must run in a session with access to the user's desktop; an unavailable desktop or file manager produces an error.
5. Drag a file or folder onto another folder to move it. Existing destinations cannot be overwritten, and a folder cannot be moved into itself.
6. A capable Node opens a complete UTF-8 text file in edit mode by default. Change the default to read-only under **Settings > Appearance**, or switch the current preview from its title bar. Use `Ctrl/Cmd+S` or Save to write, `Ctrl/Cmd+F` to find, `Ctrl/Cmd+H` to find and replace in the same panel, and `Alt+M` to open symbols and jump to a class, function, or heading. Completion uses only the current document and basic language syntax; it is not a project language service. Text larger than 1 MiB remains editable and saveable, but uses plain-text mode without syntax parsing, symbols, or completion to keep browser memory bounded.
7. On a Node with code navigation, hold `Ctrl/Cmd` over a code symbol to identify a jump target. Candidates list definitions before references. Selecting a target opens a new tab at the top of the file preview, focuses and selects the target line. Within the file preview, use `Alt+Left` / `Alt+Right` to go back and forward through code jumps and manual file-tab switches, restoring the cursor position; closed tabs are removed from navigation history. The first source preview builds a local index in the background, and a jump waits for that same build if it is still running. TypeScript/JavaScript, Python, Java/Kotlin, Go, Rust, C/C++, and C# are formally supported; other Ctags parsers are best effort. If the symbol index reaches its size limit or code-navigation resources are unavailable on the Node, the navigation area shows a local notice instead of a global error or a misleading no-match result. File browsing, editing, and saving remain available.
8. Ctrl/Cmd-click a file to open it in one reusable companion Console window while keeping the conversation visible. The window automatically selects the target Workspace and uses the same full-screen file tabs, editing, saving, find, and code-navigation capabilities as the main window. Later opens accumulate or activate files in that Console without reloading it or creating more windows; `Ctrl+R` keeps it in file-window mode and opens the most recently opened file. Right-click text or Git Diff content for Copy, Paste, Select all, Quote, and Reload; Paste is unavailable for read-only content, and reloading unsaved edits requires confirmation. Rendered Markdown uses a separate page without file tabs, while ordinary Markdown opens as source text first.
9. For a Markdown file, use the preview icon in its title bar to open a rendered page. The independent page always uses a light appearance, regardless of the console theme, with a print-friendly A4 body; refresh the browser to update its content. Preview settings can enable a browser-wide text watermark; its enabled state and text are stored only in this browser. There is no theme selector. Mermaid diagrams are supported; relative links and images remain limited to the current Workspace, while `http`/`https` images load directly in the browser.
10. HTML/HTM files still open as source by default. Use **Preview** in the file menu, the source preview button, or `Ctrl/Cmd+Shift+V` to show the saved version in the Aside browser; this does not save drafts. The source window is temporarily hidden while its tabs and drafts remain available via **Open source**. Wait for any save to finish before previewing. A Workspace HTML link in a conversation opens in the browser; Ctrl/Cmd-click opens a rendered page in a new window. Ctrl/Cmd-click in Files still opens the source window. The first preview opens a closable Browser tab alongside sessions to the right of the fixed tools; no Browser tab appears before that. It shows one file at a time, replacing the previous page. The header keeps the file name, with icons to reload, open source, or open in an external browser. Close the tab with × without discarding source drafts; reopen the source from Files. Preview from a companion source window remains a separate page. HTML can run scripts, load resources in its directory and descendants, and send files externally. Preview trusted files only. An administrator can configure a separate HTTP or HTTPS preview origin; otherwise the Console origin is used and **HTML runs with your signed-in permissions, without isolation from the workbench**. A separate origin requires DNS, TLS when using HTTPS, and a reverse proxy to the Server preview route. Cross-origin content cannot deliver keyboard events to the Console; focus the preview header before using close shortcuts.

Standalone rendered Markdown/HTML pages retain the browser's native context menu instead of the custom menu used by ordinary file pages.

File and Diff read failures show a short reason and **Retry** inside their content area, keeping the file title and close action without a duplicate global error message. Retry reads the same target without adding a file tab. Files and Git list failures likewise stay in their own lists with a retry action. Unsupported or failed previews offer download instead; a binary Diff or a Diff without displayable text can open the file preview when available.

The unified preview supports code and text, common images, PDF, DOCX, XLSX, PPTX, common video, and audio. The workbench renders PDF pages itself and does not depend on the browser's built-in PDF viewer. PDF and media are read on demand. Modern Office files are parsed locally in the browser and are not sent to an external preview service. PPTX previews are constrained by both available width and height, preserving the complete slide ratio in very wide or short windows. Legacy DOC, XLS, and PPT files and other unsupported formats keep a download action. A damaged or oversized Office file may also fall back to download.

Legacy text previews recognize BOM-marked UTF-16 and automatically try GB18030 for known text files when UTF-8 decoding fails. Damaged text can fall back to UTF-8 with replacement characters. The preview identifies fallback decoding and always remains read-only; it does not convert or overwrite the source file. Unknown binary formats still fall back to download. Git Diff displays the patch returned by Git rather than recomputing differences from decoded previews; a non-UTF-8 worktree does not suppress a text patch, but Git-reported binary differences remain unsupported for text comparison.

In ordinary Work mode, chat file and image links support absolute paths readable by the Node service account, including session image directories outside the Workspace. Relative paths still resolve within the current Workspace. Absolute paths are for read-only preview and download; they do not expand the file tree, search, or write scope and do not apply to hosted conversations. **Users with Workspace access can read other host files available to the Node service account by their absolute paths; Workspaces and allowed roots are not file confidentiality boundaries.** When sharing a Node, isolate sensitive data through the service account and operating-system file permissions.

**Success:** The preview title matches the selected tree path, and refreshing the tree shows the real file-system state.

## Troubleshooting

- If canceling or removing a task reports that temporary upload cleanup could not be confirmed, the task stays visible instead of silently disappearing. Retry or ask an administrator to check the Node's temporary uploads. Refreshing the page does not confirm cleanup.
- Workspace direct uploads verify the complete file's SHA-256; a mismatch leaves the target unchanged. An interruption after upload starts reports an error, without automatic retry, reauthorization, or a new upload through the Server. Click Retry yourself; after refreshing the page, select the same unchanged source file with the same name and size. Fresh authorization then resumes from the continuous offset confirmed by the Node. Expired temporary uploads and Node restarts require a new upload. Server upload fallback remains available before direct upload starts; existing download and preview fallback behavior is unchanged.
- Operation denied: check the Node service account permissions, Workspace boundary, and resource authorization.
- Regular-expression search unavailable: regular-expression mode requires the Node-bundled `rg` resource. Reinstall or upgrade that Node, then try again; plain-text search can still fall back when the resource is missing.
- Long file name: hover the tree row to confirm its full relative path before moving or deleting it.
- Read-only preview: write-incompatible Nodes, truncated text, Diff, and Git History content remain read-only. Nodes below the business baseline must first be [upgraded](../deployment/upgrade.md).
- Save conflict: an Agent, terminal, or another window changed the file. Discard the local edit, reopen the file, review the latest content, and edit again; the workbench does not force an overwrite.
- A Diff opens instead of a file: chat file changes and Git text changes open Diff by default. Supported images, audio, video, PDF, and Office formats in Git Changes / Git History open directly in a preview of the corresponding worktree or selected commit. Unknown binary files and unsupported formats retain fallback actions.
- Office preview fails: verify that the file is DOCX, XLSX, or PPTX rather than a legacy file with a renamed extension, then use Download if needed.
- Dragging has no effect: refresh the tree and confirm the destination is writable and inside the Workspace.
- A new tab is blocked: allow pop-ups for MyAgentRoam. Executable HTML on the Console origin may use the current account's existing permissions.

File operations act on the real Node directory. There is no hidden recycle bin. Check Git Changes or create a backup before renaming, moving, overwriting, or deleting. Next: [Git Changes and Diff](git-changes.md).

After selecting file or Diff text, use that menu to [add a quote](file-reference-and-attachment.md#quote-a-selected-excerpt). Select all covers only the currently loaded document; it does not quote automatically or read other files. The mobile bottom toolbar provides direct actions without a More button; text selection and content context menus are unchanged.
