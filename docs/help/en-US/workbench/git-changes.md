# Git Changes and Diff

When the Workspace is a repository subdirectory, Git uses the containing repository by default. Paths are relative to each repository root and may include files outside the Workspace. Git current-file previews and downloads use that repository target and remain read-only; they never save a same-named Workspace file. Revert affects the file in the listed repository. For ordinary editing, open files inside the Workspace through Files. Disable **Use parent Git repository** in Workspace details when unnecessary; ordinary Files and sessions remain available.

The repository title, branch, and Refresh button share the first row; status tags appear on the second row. When commits are not synchronized, a tag shows `↓ incoming count ↑ outgoing count`, with the upstream and an explanation on hover. Counts are independent of uncommitted file changes and compare only the locally known upstream. Opening the tab or refreshing manually first reads and displays local status, then attempts to fetch the root repository and readable initialized submodules in the background. Status is read again only when refs changed; an unchanged fetch does not cause another read. If the update result cannot be confirmed, status is read again to avoid missing updates. Other local refreshes remain available. Within the same page, Changes fetch attempts for the same Node and Workspace start at least 30 seconds apart, including failed attempts. While a fetch is running or the interval has not elapsed, only local status is refreshed; no later fetch is queued, and switching Workspaces does not reset the interval. Linked worktrees share the root's remote refs and are not fetched twice. If fetching fails, local records remain available with a subtle orange text notice, cleared after the next successful fetch. The page never pulls, pushes, or switches branches. The tag is hidden when there is no available upstream, HEAD is detached, or both counts are zero.

Git Changes shows the current root repository, initialized submodules, and every linked worktree as peer groups in one list. Tags identify the root, submodules, worktrees, and the current worktree. Each linked worktree group shows its full physical absolute path on the Node, together with its branch or detached HEAD and any locked, prunable, or unavailable status. Every group lists its modified, added, deleted, renamed, and untracked files.

Each read returns at most 1,000 changes across all groups. Affected repositories show a notice if that limit or the Git output limit is reached. Scroll to the bottom to progressively display the returned changes, without a manual load-more control; this does not retrieve files beyond the limit.

On mobile, drag anywhere on the minimap to move through the file. The bottom-right action group uses two rows: file and change navigation above, then find, download, and close below.

Select a text file to open its working-tree Diff in the unified file-tab strip. Ctrl-click (Command-click on macOS) the file to open the same content in a separate window through the standard file preview/editor flow, then use the previous/next controls and minimap to navigate changes. Ctrl/Cmd-click a recognized code symbol or import path in a Working Tree Diff to request controlled navigation; deleted lines are not navigable. Ctrl/Cmd+E opens the corresponding working-tree text tab for editing, while a History Diff opens only that commit's read-only text tab. Diff, fallback preview, and restore actions in a linked worktree operate on that physical worktree rather than a same-named path in the current Workspace. Supported images, PDF, Office, and media formats open directly in file preview without an extra **Open file preview** step. Git Changes reads the corresponding worktree version; Git History reads the selected commit, never the current worktree. Unknown binary files and unsupported formats retain file information and fallback actions.

You may revert tracked changes or delete untracked files after confirmation. These actions affect the real Workspace and cannot be undone by MyAgentRoam. Stage, commit, branch, and remote operations remain available through your normal Git tools or terminal.

If a branch or status is stale, use Refresh or press `Ctrl+Shift+K` (`Command+Shift+K` on macOS) to reread every group and attempt a background fetch under the limits above. The shortcut opens Git Changes and also refreshes it when already visible. The Files tab continues to browse only the current Workspace; linked worktrees are exposed through Git Changes rather than added to that file tree. Git features are unavailable for ordinary directories.

In the Work view, a new Run completion notification for any session in the current Workspace automatically refreshes the visible Git Changes or Files tab. The completed session need not be selected, and read notifications also trigger refresh. A session becoming idle does not trigger this refresh on its own; if no completion notification arrives, refresh manually or reopen the tab. Other Workspaces and hidden tabs are not refreshed. Existing content remains visible during refresh or after a failed read; use Refresh to retry.

If a submodule or linked worktree cannot be read, changes from other readable repositories remain available. The affected group shows its unavailable status, reason, and error code. For example, a directory tracked as a gitlink without a matching `.gitmodules` configuration shows `GIT_SUBMODULE_MAPPING_MISSING`. Uninitialized submodules and missing directories are also marked individually, without automatic initialization or deletion. A locked marker alone does not prevent a worktree from being read.

An unreadable root repository, a non-Git root, or a missing Git executable still fails the entire read. Ask the repository maintainer to repair the submodule configuration, directories, or permissions, then refresh. The page does not create `.gitmodules`, modify gitlinks, or switch branches. Background status updates and Run completion refreshes do not fetch.
