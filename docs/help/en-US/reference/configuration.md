# Configuration Reference

Server deployment configuration includes the public HTTP/HTTPS origin, MySQL connection/credentials, persistent data directory, and optional read-only SSH directory for repository sources. Secrets belong in protected environment or deployment files, never in Web assets.

| Configuration                                                                     | Owner                    | Purpose and change handling                                                                                                                   |
| --------------------------------------------------------------------------------- | ------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------- |
| `MAR_PUBLIC_ORIGIN`                                                               | Server environment       | Browser-facing HTTP/HTTPS origin and OAuth callbacks; restart Server after changes.                                                           |
| `MAR_SERVER_HOST`                                                                 | Server environment       | Listener address; Quick Start defaults to `127.0.0.1`; set `0.0.0.0` for external binding. Restart Server.                                    |
| `MAR_SERVER_BIND_ADDRESS`, `MAR_SERVER_PUBLIC_PORT`                               | Compose environment      | Published host address and port, default `127.0.0.1` and `5190`; expose the intended entry point for direct HTTP. Recreate Server.            |
| `MAR_SECURE_COOKIES`                                                              | Server environment       | Secure defaults to the public origin scheme; set `true` or `false` only for an explicit override. HTTP needs no extra opt-in. Restart Server. |
| `MAR_WEB_PUSH_SUBJECT`                                                            | Server environment       | Independent VAPID contact using `mailto:` or HTTPS; defaults to an HTTPS public origin when unset. Restart Server.                            |
| `MAR_DATABASE_URL`                                                                | Server environment       | Sensitive MySQL connection; restart Server after changes.                                                                                     |
| `MAR_DATA_DIR`                                                                    | Server environment       | Server persistent data directory; protect the path and restart Server after changes.                                                          |
| `MAR_SERVER_SSH_DIR`                                                              | Compose environment      | Sensitive absolute `.ssh` directory of the deployment account; recreate Server after changes.                                                 |
| `MAR_SEARXNG_SECRET`                                                              | Compose environment      | Sensitive SearXNG service secret; recreate SearXNG after changes.                                                                             |
| `MAR_SKILL_CACHE_MAX_BYTES`                                                       | Server environment       | Skill cache limit, default 10 GiB; restart Server after changes.                                                                              |
| `serverUrl`, `allowedRoots`, `dataDirectory`                                      | Node private JSON        | Server connection, permitted Workspace roots and private storage; restart Node after changes.                                                 |
| `directTransfer.udpPortRangeBegin`, `directTransfer.udpPortRangeEnd`              | Node private JSON        | UDP range for authorized LAN direct connections; restart Node after changes.                                                                  |
| `conversationHosting.enabled`, `computerUse.enabled`                              | Node private JSON        | Security-sensitive capabilities managed from Node details; supported changes apply without a manual restart.                                  |
| `conversationHosting.storeDirectory`, `conversationHosting.inactiveRetentionDays` | Node private JSON        | Hosted conversation storage and permanent inactivity retention; stop Node and back up before changing, then restart.                          |
| `MAR_CLAUDE_CONTEXT_WINDOW_TOKENS`                                                | Node service environment | Claude Code context-window display limit; restart Node after changes.                                                                         |
| `MAR_AGENT_WEB_FETCH_ALLOW_UNTRUSTED_TLS`                                         | Node service environment | Security-sensitive certificate-validation setting; restart Node after changes.                                                                |

Node package-version checks and Supervisor installation use the respective service account's standard npm configuration. When Server and Node run as different accounts, configure each account separately; do not put npm credentials in Node JSON.

`MAR_SEARXNG_SECRET` is required by Compose and must contain a long random value used only by the private SearXNG service.

Node private configuration includes the Server URL, first-registration token or persisted identity credentials, data directory, and `allowedRoots`. The Node writes identity after registration; protect the complete file and data directory. Agent and provider configuration remains owned by each Agent under the Node service account. Configure sensitive values through [Environment Secrets](../administration/secrets.md), not in public examples or Git.

Under **System Configuration > HTML preview origin**, an administrator can set an HTTP or HTTPS origin on a different hostname, such as `https://preview.example.com`. Set the Console's `MAR_PUBLIC_ORIGIN` first, then configure DNS, TLS when using HTTPS, and a reverse proxy that forwards only the same Server's preview resource routes. Changing the port alone does not isolate cookies. An empty setting uses the Console origin: HTML/JS then runs with the signed-in account's permissions, without workbench isolation. HTML can load files in its directory and subdirectories and make external requests; run only trusted files.

Authorized ordinary Workspace file, Git, and terminal direct connections share the UDP port pool `49152-49215` by default. At startup, each Node process obtains one free port from its configured range and uses ICE UDP Mux so every Probe, file-transfer, and terminal connection in that process reuses the same port. Override the pool with both `directTransfer.udpPortRangeBegin` and `directTransfer.udpPortRangeEnd`; values must be within `1024..65535`, ordered, and span no more than 256 ports. Set both values to the same port for a fixed single-port deployment, or assign non-overlapping ports or ranges when multiple Nodes require isolation. Permit the configured range only from the actual browser LAN. Exhausted or blocked ranges do not prevent Node connectivity; supported file and terminal operations can use Server relay, while an interrupted operation may need retrying.

On a supported online Linux Node, a system administrator can enable Bubblewrap-hosted conversations from Node details. The Node writes `conversationHosting.enabled` to its private configuration and initializes hosting immediately. Existing directory and retention settings are preserved; when absent, the Node uses `hosted-conversations` and `60` days. `conversationHosting.storeDirectory` must be a non-empty relative directory inside `dataDirectory`; absolute paths, `.` and `..` segments, and paths that escape the private data directory are rejected. `conversationHosting.inactiveRetentionDays` accepts `1` through `365`.

Node details can also disable hosting. Disable preserves the hosted directory, SQLite index, and conversation history, but Node rejects the request while a hosted Run is active or starting; it never cancels that Run. Stop Node and back up the private data before changing the directory or retention setting. Automatic inactivity cleanup permanently deletes threshold-qualified conversations. A user-confirmed conversation deletion is also immediately permanent and has no recovery window.

`computerUse.enabled` defaults to `false` when omitted. Use the Node details switch instead of editing it manually. Enabling asynchronously downloads or reuses the exact managed runtime npm package, verifies and installs it in Node-private storage, and probes the current interactive desktop. Node never invokes pip or falls back to system or Workspace Python. An unpublished, failed, or damaged package leaves the capability unavailable with a stable reason. `computerUse.runtimeExecutable` is reserved for development and validation overrides and should not be used in production configuration.

Use the exact names and examples in the current release deployment files. Restart the owning service after changing startup configuration and verify health before proceeding.

Skill content is stored under `MAR_DATA_DIR/skills`, Server logs under `MAR_DATA_DIR/logs`, and Node logs under `dataDirectory/logs`. Logs also go to standard output, rotate daily or at 100 MiB, and are retained for seven days. Server warns when estimated Skill cache use exceeds 80% of its limit and stops new favorites and favorite upgrades above 90%; reading and installing existing cached content remain available.

`MAR_AGENT_WEB_FETCH_ALLOW_UNTRUSTED_TLS` defaults to `1`, so MAR Agent Web Fetch accepts self-signed or otherwise untrusted HTTPS certificates. Set it to `0` in the Node service environment to enforce certificate verification, then restart the Node. This setting is security-sensitive.

All deployments require a valid real host UUID. Containers must mount `/sys/class/dmi/id/product_uuid` read-only at `/license-host/product_uuid`; the source must exist. Native deployments may use `MAR_LICENSE_HOST_PATH` to select the real UUID file. Community and Enterprise share this requirement.
