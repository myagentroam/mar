# 登记第一个 Workspace

工作区（Workspace）是一台 Node 上可在工作台中打开的真实目录。它不是文件副本，也不能跨 Node 使用。

## 前置条件

Node 已在线，且目标目录在该 Node 配置的 `allowedRoots` 内；Node 运行账号对目录有相应读写权限。

## 步骤

1. 打开“工作”，展开目标在线 Node，点击新增工作区入口；登记弹窗使用此次操作的目标主机，不改变当前工作区。
2. 从 Node 返回的可选目录中选择 `allowedRoots` 之下的目录，并设置易识别的工作区名称。
3. 保存成功后立即打开该工作区标签，并后台加载内容；取消弹窗则保留原工作区。
4. 打开文件面板确认根目录、必要时打开 Git Changes。

**成功标志：** 工作区出现在所选 Node 下，文件树可读取；Git 仓库还会显示 `Git` 和当前分支标签，并提供 Git Changes。

可以直接登记 Git 仓库的子目录，无需改为仓库根。默认开启“使用父级 Git 仓库”：Git 视图包含整个所属仓库，文件树、搜索、普通编辑和会话执行目录仍限定在所选 Workspace。不需要时，在工作区详情的 Git 配置中关闭；重新开启即可恢复。设置会保留，且关闭不会停用 Workspace 自身的 Git 仓库，也不限制 Agent 或终端运行 Git。

如果其他用户登记的工作区尚未显示，可在工作树空白处右键选择“刷新工作区”，更新节点和已加载的工作区列表；也可以在目标 Node 上右键选择“刷新工作区”，仅更新该节点的工作区。

## 失败排查

- 路径不在 `allowedRoots`：修改 Node 私有配置并重启服务后重新登记，切勿用软链接绕过边界。
- 文件不可读或无法写入：修正 Node 服务账号的目录 ACL/所有权。
- Git 功能不可用：普通目录仍可作为 Workspace；仅 Git 视图不可用。

## Git 覆盖策略

支持个人 Git 配置的 Node 在登记时提供“不覆盖 Git 参数”。默认不勾选；勾选后新执行保留 Node／仓库原有身份与认证。重新登记已有目录不会重置已保存策略，后续由工作区管理者在详情中修改。用法及凭据匹配见[终端中的个人 Git 配置](../workbench/terminal.md#个人-git-身份与凭据)。
