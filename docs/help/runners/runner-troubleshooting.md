# Agent 不可用或模型缺失

先区分内置 MAR Agent 与外部 Agent，避免反复刷新或重装不相关的 CLI。

## 内置 MAR Agent

1. 确认 Node 在线且“支持 Agent”包含 MAR Agent；它随 Node 内置，不需要安装外部 Agent CLI。
2. 请管理员在“管理 → MAR Agent 模型”确认模型配置存在且已启用。普通用户须具有模型使用授权；包括系统管理员在内的使用者都须位于绑定凭据的作用域内。
3. 使用 Codex 凭据的模型还需由凭据管理者检查凭据是否需要重新登录、代理是否可用。模型管理权不自动授予其他用户个人凭据的查看权。
4. 请管理员选择兼容的在线 Node 执行模型“测试”，按结果处理连接、认证、模型或传输配置问题。凭据测试与实际 Node 模型测试不是同一项验证。
5. 返回工作区重新选择有效模型；没有可用模型时先修复配置或授权，不要通过删除历史或安装 Codex CLI 解决。

配置步骤见[MAR Agent](mar-agent.md)。

## Codex、Claude Code 与 OpenCode

1. 在 **Node 服务实际运行账号** 下执行对应 CLI 的 `--version`；不是在管理员或 SSH 登录账号下。
2. 确认该账号的用户目录（Linux 为 `HOME`，Windows 为用户配置目录）、`PATH`、Agent 登录和服务提供商配置与前台验证一致。
3. 查看 Node 详情的“支持 Agent”，等待最多一个发现周期或重启 Node。
4. 对 OpenCode，确认 Node 服务账号的全局配置明确声明了服务提供商和模型；仅配置在工作区中的模型不会显示，不依赖 Gateway 自动发现。
5. 检查 Node 到外部登录或模型服务的网络，以及工作区的目录权限。

| 现象                | 常见原因                         | 处理                                                     |
| ------------------- | -------------------------------- | -------------------------------------------------------- |
| 外部 Agent 不显示   | CLI/PATH/登录态不在服务账号      | 修正服务 unit/任务计划 HOME 与 PATH 后重启 Node          |
| MAR Agent 模型为空  | 模型禁用、授权或凭据作用域不满足 | 请管理员检查 Server 模型与凭据，不修改工作区 CLI 配置    |
| 外部 Agent 模型为空 | 原生模型服务配置不生效           | 修正对应 Agent 的服务账号配置；OpenCode 使用全局模型配置 |
| `SESSION_INVALID`   | 会话保存的模型配置已不再可用     | 刷新后选择当前模型，必要时新建会话                       |
| 节点高负载时详情慢  | 同时运行的 Agent 较多            | 等待“支持 Agent”更新，查看主机负载和 Node 日志           |

不要把 Agent 配置、访问令牌或完整日志贴到公开工单。仍无法恢复时，按[快速诊断](../troubleshooting/quick-diagnosis.md)收集版本、时间、错误码和请求 ID，再联系部署管理员。
