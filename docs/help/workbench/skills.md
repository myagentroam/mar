# 查找与配置 Skill、MCP

可配置目录和已加入目录每页向服务端读取 20 条，搜索、排序和分类覆盖完整可见目录；标签分类不随当前页或搜索结果缩小。来源定义和当前目标的已安装 Skill/MCP 是完整配置快照，直接全部展示，不分页。已安装项即使失去目录引用仍保留，但只能使用原有合法操作，不能借此重新安装或更改继承配置。

“管理”菜单中的“技能配置”同时提供 Skill 与 MCP 两类 Agent 扩展。Skill 为 Agent 提供可复用的操作说明和工作流；MCP Server 让 Agent 连接浏览器、业务系统或其他工具。两者都可以配置到节点或工作区：节点配置对该节点上的工作区生效，工作区同名配置优先。

技能配置直接展示当前用户可用的企业、组织和个人目录，并用于将目录项安装到节点用户目录或工作区。页面默认在“可配置技能”Tab 选择并安装 Skill，“当前目标中的技能”Tab 用于查看、更新、重新安装或删除目标目录中的 Skill。

打开 Workspace 后，可点击会话栏“新建会话”右侧的“更多”按钮，再选择“已加载技能”，只读查看 Agent 在该 Workspace 实际可用的技能。列表同时包含节点用户目录与 Workspace 技能并标注来源；名称相同时以 Workspace 技能为准。安装、更新和删除仍在“管理 → 技能配置”中完成。

## 管理来源与可用技能

1. 打开“管理 → 技能源管理”。下方默认进入“源内技能”Tab，在下拉框选择已启用的来源；页面会自动加载该来源的技能，skills.sh 默认显示缓存 24 小时的 Hot 热门榜，也可在下方输入名称或描述后搜索。“已加入的技能”Tab 用于维护已经加入可用目录的技能。
2. 点击技能卡片的“加入可用目录”，选择个人、组织或企业范围；可同时启用星标推荐并添加最多 10 个 Tag 标签。标签下拉提供当前账号有权查看的已有标签，也可以直接输入新标签。加入后可按名称、描述和分类标签筛选，可查看详情，或编辑星标和标签。
3. 已加入目录的技能显示当前 Commit 短版本和更新时间。“检查更新”只比较原仓库最新 Commit，发现新版本后再由用户确认更新；目录更新后，Node 或 Workspace 不会自动变化。

星标技能会优先出现在技能配置的可配置目录中，Tag 用于说明技能用途。更新技能内容不会改变已有星标和 Tag。

仓库源必须具备可识别的 Git 版本，不接受直接下载地址。公开仓库可使用 HTTPS，支持 GitHub，以及使用标准接口的 GitLab.com/自托管 GitLab；SSH 仓库使用 `git@host:owner/repo.git` 格式。Compose 部署会把独立部署账号的完整 `.ssh` 目录只读提供给 Server，具体配置见[配置项参考](../reference/configuration.md)；连接时跳过主机指纹校验。仓库根目录或标准技能目录均可，系统会拒绝指向本机、私网或链路本地地址的来源。每个用户都可以添加自己的个人源，而且只有本人能查看和管理；企业或组织源需要相应管理权限。默认 `skills.sh` 源可停用但不能删除。

TLS 证书校验默认启用。企业管理员可在“管理 → 系统配置”打开高风险的关闭开关，以兼容自签名来源；该设置不会放宽来源地址校验。

## 安装到节点或工作区

1. 打开“管理 → 技能配置”，直接在页面中选择在线节点以及安装位置；安装到工作区时再选择该节点下的工作区。
2. 节点或工作区切换后会自动检查环境，也可手动点击“检查环境”，随后执行“安装”“更新”或“重新安装”。页面选择独立于工作台资源树，不会切换当前打开的工作区。
3. 节点以 `~/.agents/skills` 为主目录，并在首次安装时检查或创建 `.claude/skills` 兼容链接；若已有目录不能安全链接，则维护兼容副本。
4. 工作区同时维护 `.agents/skills` 和 `.claude/skills` 两份副本，并将受管目录写入本地 `.git/info/exclude`，不会修改版本化 `.gitignore`。

安装由节点在后台下载、校验并写入目录；页面会等待完成后刷新状态，耗时较长时在对应卡片显示进度，无需重复点击或刷新。安装失败会释放当前目标，处理错误原因后可以再次安装；状态确认超时时应先刷新目录确认真实结果，再决定是否重试。浏览器断开或服务重启不会自动重复安装。

系统不会覆盖人工修改的判断结果；无法识别已安装版本时会显示“版本未知”，可以从技能配置重新安装。

技能配置提供名称/描述搜索和“全部 + 分类标签”筛选，技能卡片可查看详情并在页面内容区内独立滚动。手动“检查环境”会弹窗显示兼容模式、技能数量和待修复项；Workspace 环境检查发现 Git 本地排除规则异常时，可点击带工具图标的“修正环境”，确认后重新生成 MAR 维护的规则块，取消不会修改 Workspace。

## 平台与失败处理

Linux 与 Windows 均支持节点和工作区技能；Windows 不能创建目录链接时会使用受管副本。节点离线、版本过旧、目录权限不足、技能根目录指向 Workspace 外部，或工作区 Git 排除文件不可写时，界面会禁用操作或显示明确错误。单个技能名称位置若为链接，重新安装会原子替换该链接且不会修改链接指向的外部内容；MAR 不会跟随或覆盖越界的技能根目录。

## 使用 MCP Server

### 将 MCP Server 加入中心

1. 打开“管理 → MCP 源管理”。系统已提供官方 MCP Registry；也可以新增兼容 Registry，并选择个人、组织或企业范围。
2. 选择一个已启用来源，按名称或说明搜索 MCP Server。可先点击“详情”核对 Server 名称、连接方式和固定版本，再点击“加入可用目录”，设置可见范围、推荐状态和标签；标签可以从当前已有标签中选择，也可以直接输入新标签。
3. 在“已加入的 MCP”中可查看详情、编辑推荐和标签、检查 Registry 更新、确认更新或移除。更新可用目录不会自动改变已经配置到节点或工作区的版本。
4. 返回“管理 → 技能配置”，切换到“MCP”Tab，即可浏览当前账号可用的 MCP Server；可按名称或说明搜索，也可使用“全部 + 标签”切换分类，并可在选择目标后直接安装。

目录只保存固定版本，不使用会在未来自动变化的 `latest`。新增或升级版本不会自动改变节点与工作区中的现有配置，需要用户明确安装。

### 配置到节点或工作区

1. 打开“管理 → 技能配置”，切换到“MCP”Tab。
2. 选择“节点”或“工作区”，然后选择在线目标。节点配置适合多个工作区共用；仅某个项目需要的 MCP 应配置到对应工作区。目标离线、停用、版本不支持、工作区缺失或权限不足时，页面会保留具体原因，不再只显示笼统的不可用提示。
3. 在“可配置 MCP”Tab 可查看详情并点击“安装”；已经安装旧版本时按钮显示“更新”。安装由目标 Node 使用其运行账号的本地命令环境执行：`npx` 可按用户自己的 npm 配置下载和缓存固定版本，MAR 每次都会完成 MCP 初始化和工具读取验证，并至少确认一个可用工具，耗时较长时卡片会显示进度。只有验证完成才会保存配置并提示成功；失败时可先在 Node 终端修正 npm、网络、鉴权或系统依赖后重试。安装成功后只影响随后新建或重新打开的 Agent 会话，不修改已经运行的会话；删除配置不会清理用户的 npm/npx 缓存。
4. 在“当前目标中的 MCP”Tab 可查看详情、启用、停用、更新、重新安装或删除。工作区删除同名配置后，若节点仍配置了该 MCP，新会话会继续使用节点配置。
5. 在节点工作台中，点击“新建会话”右侧的“…”并选择“已加载 MCP”，可以在创建会话前确认该 Workspace 最终启用的 MCP 及其来自 Workspace 还是 Node。被 Workspace 同名配置停用的 Node MCP 不会出现在这里。

MCP Server 的环境变量和请求头只引用“环境密钥”中已有的环境变量名，页面和保存记录不会包含密钥值。引用的环境密钥不存在时，该 MCP 不会注入 Agent 会话，应先在“管理 → 环境密钥”补齐。

### 使用 Playwright

在官方 MCP Registry 中搜索 Playwright，将需要的固定版本加入可用目录并安装到目标后，Agent 即可在浏览器中打开页面、交互、截图和验证 Web 功能。Playwright 不是不可删除的内置目录项，可从可用目录、节点或工作区移除。默认配置具有以下边界：

- 使用无头浏览器，不弹出本机浏览器窗口；
- 每个 Agent 会话使用独立浏览器上下文，不共享 Cookie、登录态或页面；
- 会话结束后不保留浏览状态；需要登录时，应在当前会话内完成；
- Node 主机需要能够执行该 MCP Server 的固定 npm 包版本并访问待测页面。

如果 Agent 无法调用 Playwright，先确认目标节点在线、Node 版本支持 MCP、Playwright 已安装到正确的节点或工作区，并新建一个会话重试。运行中的旧会话不会热加载刚安装的 MCP。
