# 使用 Workspace 终端

移动端点击会话标题栏的“打开终端”，终端会从底部向上展开为全宽半屏浮层。点击上方遮罩关闭只隐藏浮层，不结束终端；重新打开会保留原有标签。需要结束进程时显式关闭终端标签。

终端以 Node 固定服务账号启动，选择 Workspace 后以其目录作为 cwd；不接受网页提供的系统账号、密码或提权参数。

## 前置条件

Node 在线，当前用户有目标 Workspace 运行权，且该 Node 仍有可用终端容量。新终端继承 Node 服务环境、当前授权密钥快照，以及按工作区策略启用的个人 Git 配置。

## 步骤

1. 点击页面底部“展开终端”；展开前不创建或连接终端。首次展开当前页面的工作区时会创建一个新终端，也可以用标签栏末尾的加号再创建一个。其他浏览器页面不会接管这里的终端。
2. 使用正常 Shell 命令检查文件；桌面端选中文本不会自动复制。右键始终打开菜单，可复制终端选区、粘贴浏览器剪贴板，或用“清屏”清除当前终端显示与回滚内容（保留当前光标行，不结束进程，也不向 Shell 发送命令）。Vim 等程序启用鼠标模式时，可按住 Shift（Windows/Linux）或 Option（macOS）拖选终端文字再复制；Vim 内部的可视选区不是终端选区。
3. 桌面端输出中的 HTTP(S) 地址悬停时会显示链接样式；按 `Ctrl` + 点击（macOS 为 `Command` + 点击）在新浏览器标签页打开。普通点击不会跳转，本地路径和其他协议暂不处理。
4. 折叠 Dock 不会终止终端；需要结束时显式关闭标签。

**成功标志：** 提示符位于 Workspace 目录，断线后短暂重连仍能收到有限回放输出。

当浏览器与 Node 的局域网直连可用时，节点级与 Workspace 级终端会在授权后使用直连传输；否则使用 Server 中继。连接中断时会自动切换或重试，并从最近的输出序号继续回放；无需手动选择路径。直连仍由 Server 授权、续期，终端命令与写入权限由 Node 校验。若权限失效或终端已关闭，自动重连会停止。

终端上限为每 Node 10 个、每 Workspace 5 个；Node 重启会关闭所有终端。移动浏览器受系统键盘和后台策略限制，建议进行查看和短命令，长操作使用桌面端。

安全提示：新建终端会得到授权的密钥环境快照，命令和程序可能读取其值；不要把 `env` 输出、密钥或终端截图公开。

下一步：[终端无法打开或频繁断线](../troubleshooting/terminal.md)。

## 常见失败

- 创建失败：确认 Node 支持终端、Shell 可启动且没有达到容量上限。
- 输出中断：先等待自动重连；若 Node 重启或权限变化，创建新终端。
- 复制或粘贴无效：浏览器可能拒绝剪贴板权限，先在浏览器设置中授权并只粘贴已审查命令。

## 个人 Git 身份与凭据

在“设置 → Git 配置”为每条远程凭据填写完整 Git 远程地址或 SSH 主机规则、提交姓名和邮箱。两项一起设置或一起清空，并始终随该凭据使用；添加 HTTPS Token／密码或 SSH 私钥。SSH 私钥支持 OpenSSH 或 PEM 格式；只有加密私钥需要填写解锁口令。表单只会在保存时校验，因此可以完整粘贴地址和私钥。敏感值保存后不回显，编辑时留空保留，勾选移除口令可以清除已保存口令。

远程地址可以填写 `https://git.example.com/team/project.git` 或 `git@git.example.com:team/project.git`；系统按其中的协议、主机、端口和完整仓库路径精确选择当前用户凭据。若同一 SSH 私钥适用于某主机下的全部仓库，可以填写 `git@git.example.com`；完整仓库规则优先于同一主机规则。HTTPS 默认端口为 443，SSH 为 22。同一规则不能保存两套账号。对已有仓库执行 Git 时，提交身份随当前分支上游、或 `origin` 匹配到的凭据注入；命中完整身份时，`git config user.name` 与 `git config user.email` 显示当前有效身份，但不会写入全局 Git 配置或 `.git/config`。没有匹配规则、没有远程或未填写完整提交身份时，保留当前环境／仓库原有身份和认证。命中规则后认证失败不会尝试其他个人账号。

保存后创建新终端，照常执行 `git clone https://git.example.com/team/project.git` 或 `git clone git@git.example.com:team/project.git`，无需额外的账号选择命令。克隆只创建目录，不自动登记工作区。Agent 从普通工作区执行的 Git 命令同样使用发起者配置；托管对话不应用此设置。

登记工作区时可以勾选“不覆盖 Git 参数”，工作区详情中也可由管理者修改；该选项影响工作区所有用户。已有工作区升级后默认保留原配置，新登记默认启用个人配置。普通使用者可查看策略但不能修改。勾选后保留 Node／仓库原有身份与认证，不修改全局 Git 或 `.git/config`。低于当前业务基线的 Node 需先[升级](../deployment/upgrade.md)，不能用于工作区操作。

终端固定使用创建者与创建时工作区策略，`cd` 不切换策略；远程凭据仍随实际地址匹配。修改配置后关闭并重建终端；已接受的队列和持续任务沿用原快照。个人 Git 配置只注入 MyAgentRoam 创建的 Agent 和终端进程，不改写主机全局 Git 配置；主机终端、IDE 或其他程序中的命令不受影响。带个人 Git 配置的终端不能由其他用户查看、附加或关闭。

HTTPS 仍校验证书；SSH 未知或变化的主机密钥会拒绝连接，请让 Node 管理者通过可信渠道维护 known_hosts，不要关闭主机校验。不要把 Token 放入仓库 URL、命令、截图或日志。
