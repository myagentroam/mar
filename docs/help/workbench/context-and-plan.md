# 上下文用量、Compact 与 Plan

上下文用量来自当前 Agent 能提供的会话数据，而不是浏览器估算。发送新消息、重新读取历史或完成上下文整理后会更新；Agent 无法提供可靠数值时，界面会显示不可用，而不会显示猜测的百分比。

触屏点按上下文用量：可压缩时打开含完整用量的确认框，确认后才执行 Compact；运行中等暂不可压缩状态下，仍可点按读取完整用量与不可用说明。

## 使用步骤

1. 在页面底部消息输入区查看上下文用量百分比；某些 Agent 也会在节点详情提供账号 Usage，两者含义不同。
2. 用量接近窗口或会话已很长时，先确认关键结论已落入文件、计划或清晰的后续提示。
3. 选择 Compact 并等待该操作明确完成；完成前不要以页面刷新判断失败。
4. 使用计划模式时先审阅计划卡；只在准备执行时选择“执行”。

Compact 会请求当前 Agent 整理可继续使用的上下文。整理期间仍显示 `Working`，完成后恢复 `Idle` 并更新后续消息可用上下文；它不会删除原有对话历史。

MAR Agent 的 Context GC 与 Compact 不同：它按确定性规则回收已过时或符合保留规则的工具内容，减少后续请求的活动上下文；Compact 则整理可供续作的语义信息。两者都不意味着无限记忆或所有旧细节始终可见；重要决定应保存在项目文件或明确的任务说明中。

MAR Agent 提供上下文用量时，指示器详情会以一行显示 GC 次数和回收 token 数，只统计最后一次成功 Compact 之后；尚未 Compact 时从会话开始统计。token 数累计 GC 前后真实请求 input 的净下降，期间新增内容会影响该值，不等于精确删除量或账单节省；尚无配对的真实用量时显示 `—`，不使用估算值。刷新保留统计，成功 Compact 后两项清零，失败或取消不清零，也不计跳过或失败的 GC 尝试。清空、回退或分叉后以保留的会话记录为准；不提供 GC 统计的 Agent 不显示这一行。

MAR Agent 还支持 Smart Compaction：有效上下文用量已较大时，主模型可在进入持续新工作、且旧细节续作价值较低时请求后台整理。这是自动启用的社区能力，无需额外设置，不替代固定容量保护。后台生成期间任务可以继续，既有整理状态项显示其生命周期，不公开内部摘要；临时问答和仍未解决的工作不应触发整理。整理后用量可能保持未知，直到前台请求报告新计量。门槛和限制见 [MAR Agent](../runners/mar-agent.md#专用-compact-模型)。

OpenCode 与 Claude Code 支持 `/plan`：开启后后续消息先用于分析和制定计划；关闭计划或选择“执行”后才进入实施。Codex 是否提供计划操作以当前页面实际显示为准。

仅当前会话的最新计划卡片在可开始新轮次时显示“执行”；最新计划即使来自较早轮次仍可能续作，更早的计划卡片不显示该按钮。

**成功标志：** 计划卡或上下文整理卡在对话中有明确开始/完成状态；选择“执行”会开启新一轮可观察的运行。

失败时先确认 Agent 可用、会话未只读，并阅读[会话卡在 Working、Idle 或只读](../troubleshooting/session-run.md)。

安全提示：Compact 不是脱敏工具，也不会替代对密钥、附件和工具输出的审查。
