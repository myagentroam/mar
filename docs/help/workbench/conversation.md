# 阅读对话、工具调用与通知

普通工作区会话中的 HTML/HTM 文件链接单击在侧栏浏览器预览，Ctrl/Cmd 点击在新页面渲染；参见[文件预览与安全说明](files.md)。

对话按用户轮次展示 Agent 文本、思考摘要、工具、命令、文件更改、计划、审批和错误。展开工具卡可查看有界的输入和结果；图片可在仍受 Node 缓存保护时预览。

展开读取文件条目可查看来源提供的实际行范围及对应正文；旧记录或未提供文件关联的 Runner 保留整次调用结果。技能、命令、网页和其他工具按可用事实展示详情；图片查看工具没有可用预览时显示元数据。结果可能因来源或显示限额而截断，复制按钮复制该次调用的公开记录，不重新读取文件或网页。

网页搜索详情显示已有查询、来源标题、链接和摘要，不再重复显示原始 Output；原始公开结果仍可通过复制按钮获取。缺少结构化来源不会从原始结果中提取链接，也不会被当成“无结果”。网页内容详情仍显示已返回的正文，错误与真实截断提示保留。

较高的详情内容会先显示有限高度的预览，点击“展开更多”可查看当前已返回的其余内容，点击“收起”恢复预览。此操作不重新读取来源，也不影响复制；`[Truncated]` 表示返回内容本身已截断，与界面收起不同。

跨会话消息的来源标题会区分父会话、子会话、更深层的后代会话和其他会话，并保留发送时的名称；悬停可查看来源会话 ID。旧消息未保存关系时仍显示原来源标签。

对话中的图片先加载缩略图，点击后打开等比详情预览；加载和解码完成后才整体显示。详情最大为 2560×2560，不放大小图；确实缩小的图片会在右上角显示“查看原图”。选择原图后加载原始图片，仍保持横纵比、完整适配弹窗，不裁切或撑出滚动条；长截图也会整体缩小显示，文字可能较小。加载失败可重试。此处理不改变上传原文件或模型收到的图片。

同一对话分段、同一聚合阶段内的思考、普通工具、命令和文件更改会分别合并为一张卡，放在该类型最后一项的位置。新增同类项目时，整组随最新项目移动，组内仍保留原始顺序；已有项目的流式内容或状态更新不会改变卡片位置。聚合不会跨越分段或用户轮次，Agent 正文之后的新活动也不会合并到正文之前的卡片。图片生成、计划、审批和问题保持独立。

上下文整理（Compact）单独显示，并在其位置分隔工作过程，包括后台整理。整理后的思考和工具进入新过程，不与整理前的记录合并；整理状态更新不会反复重新分段，也不表示当前任务已经结束。

四个 Runner 的协作操作统一显示为 **Agent 操作**，不限于父子会话。MAR Agent 支持启动、发送、等待、停止、查询和查看；其他 Runner 显示其原生提供的操作。同一工作过程、同一聚合区间内的 Agent 操作合并为一组，放在最后一次调用的位置，不按目标、操作或目标数量拆分。组头显示调用次数，展开后按原始顺序显示每次调用的工具名、已有任务名称及自身状态。

详情按来源提供的事实展示内容：启动和发送以任务名称、本次消息为主；queue／steer 仅说明发送方式，不表示已送达或已处理。等待和查看显示本次公开的状态、消息或结果，查询显示会话名称与状态列表，停止原样显示公开结果。原始输入、结果及其他已有公开字段可通过右上角复制按钮获取；记录有界，不会额外读取目标会话。缺少结构化事实的旧记录继续使用通用详情，模型信息也仅在来源明确提供的通用详情中显示。操作返回不代表目标任务结束，等待超时不代表目标任务失败；失败信息仍会保留。不嵌入目标会话的内部执行流，也不提供会话快捷跳转；需要打开目标会话时，使用会话列表或会话树。

Runner 请求或模型调用最终失败时，错误卡会显示可用的 HTTP 状态码和错误消息。普通会话中的终态失败会使会话回到 Idle，并暂停尚未执行的排队消息；确认错误原因后可恢复队列或发送新的普通消息继续。MAR Agent 在首次语义输出前可对符合条件的瞬时模型故障有限重试；活动目标也可能对失败的执行进行有限自动续作，超过边界后才阻断。

## 查看本次文件修改

支持此能力的 MAR Agent 节点会为 `apply_patch` 保存每次修改的只读 Diff，Direct 和 Code Mode 均支持。展开文件更改卡后，文件条目末尾显示可信的绿色 `+N` 和红色 `-N`；点击文件打开“本次修改”，以单栏加减行展示新增、删除、修改以及移动前后路径的实际效果。覆盖已有文件按修改展示；空文件的新增或删除仍显示路径变化及 `+0/-0`，不会凭空增加一行。

这是该次工具操作的历史记录，不是整个任务的净变更或当前 [Git 变更](git-changes.md)。同一路径的不同修改可分别打开；后续改写或删除当前文件不会改变已保存的 Diff。与标准 Diff 共用“打开源文件”按钮和 `Ctrl+E`（macOS 为 `Command+E`）：按正常文件打开流程打开当前源文件，而不是 Diff 原文。本次 Diff 始终只读，与当前源文件分开；源文件已删除或不可访问时提示打开失败，不替换已保存的 Diff。读取失败可重试，不会静默替换为当前 Git Diff。

其他 Runner、旧历史或不支持读取的节点保留原有文件打开行为；未知统计不伪造为零。非文本、超限或保存失败会明确提示无修改明细。Shell、脚本与格式化器的任意写入不在此能力范围内。清空、截断或删除会话历史时，其不再引用的 Diff 也会清理；Rewind 分支保留分支历史内的 Diff。

## 从消息创建非破坏性分支

MAR Agent、Codex、Claude Code 和 OpenCode 的终态用户消息与 Agent 回复在存在可用历史边界时，会在复制按钮旁显示 Rewind。点击后确认创建新会话分支：从用户消息操作会回到该轮之前并把原消息回填到 Composer，从 Agent 回复操作会保留该轮完整结果且 Composer 为空。

Rewind 不修改原会话，也不回滚 Workspace 文件。Working、消息提交或会话变更期间，页面隐藏 Rewind 和 Rollback；模型、推理强度、权限和手动整理上下文也不可修改，需要空闲的命令不会出现在命令列表中。复制、排队、停止和允许运行中执行的状态命令不受影响。确认弹窗后若会话开始运行或选择发生变化，不会提交操作。页面不按 Session capability 或 App Server 探测结果限制 Rewind；如果 Runner、版本或其他客户端持有的会话锁仍拒绝分支，当前会话和草稿保持不变，并显示 Node 返回的实际错误。

声明原生历史截断能力的会话，会在终态用户消息的 Rewind 后显示 Rollback。MAR Agent 支持；Codex 仅支持原生 `paginated` 会话，不支持旧式 legacy 历史；Claude Code 和当前接入的 OpenCode 历史 API 没有兼容的仅历史截断操作。Rollback 不创建分支，而是在确认后永久删除所选用户消息及其后的当前会话历史，并把原消息回填到 Composer；它不会回滚 Workspace 文件。会话必须空闲且没有排队消息；请求失败时显示实际错误，不乐观改写当前展示的历史或草稿。

对 MAR Agent 运行中补充的 steer 消息回滚时，会保留该消息收到之前的普通消息与执行记录；停止前是否已经生效不改变这一边界。

## 实时性能

Agent 提供有效的计时指标时，工作区对话右下角会出现小型 Info 图标。悬停、聚焦或触屏点按后，可查看最近一次 Latency（本轮输入到首个文本、思考、Tool Call 或其他有效模型响应的等待时间）及可用的平均输出 TPS（每秒 Token 数）。它们不属于某条消息，也不是整条工具执行链的统计；Tool 执行时间不计入 Latency，缺失指标不估算。MAR Agent 的平均输出 TPS 仅在请求结束、取得 Provider 权威输出 Token 且观测到可靠的流式生成窗口后显示，表示从首个实际生成增量到请求结束的客户端观察平均值；仅有完成态或单次、瞬时批量输出时不产生新的 TPS。可用 TPS 仍可能包含 reasoning、Tool Call、网络或 Hosted Tool 等时间，不等同于模型服务端纯推理速度。Claude Code、Codex 和 OpenCode 由 Node 按实时事件观测 Latency：提交用户输入后等待首个有效 Agent 响应；工具调用后，从最后一个已观察到的并行 Tool Result 等待下一段有效响应。该观测包含 Runner、IPC 与网络开销，不等同于模型服务端纯响应时间；这三个 Runner 当前不提供输出 TPS。

性能实时推送，不写入会话历史。运行中的过程标题也会在耗时后实时显示同一 Run 的可用指标；右下角 Info 仍然保留。同一次运行中，Latency 与输出 TPS 独立更新：新 Latency 到达时保留最近一次可用的 TPS，直到新的 TPS 到达；它们可能来自不同模型请求，新运行不继承上一运行的指标。Node 只在运行期间于内存保留最近一份指标；切回仍在运行的会话或刷新页面后会自动恢复，Node 重启后不保留。运行结束即清除 Node 中的指标；当前页面可继续显示最终值，但结束后切回不会恢复。切换会话、工作区、Node 或模式时，页面先清除原指标。消息卡片不显示性能 Info。

## 清空 MAR Agent 会话历史

在 MAR Agent 当前会话的 Composer 中输入 `/clear` 并选择该命令。确认弹窗后，系统会永久清空该会话的全部历史和会话图片，但保留同一会话、标题、工作区及当前配置；不会删除会话或回滚工作区文件。会话正在运行、存在排队消息或历史正在变更时，清空会被拒绝，原历史和草稿保持不变。

## 清理工作区会话

在支持该功能的节点上，可从当前工作区“会话”栏右上方的工作区级“更多”菜单选择“清理会话”。输入要清理多少天前的会话，默认是 30 天。操作会按各 Agent 自己支持的删除方式永久删除符合条件的原生会话；没有有效活动时间的会话固定纳入清理；置顶、活动、排队或正在查看的会话会保留。完成后页面显示实际删除、跳过和失败数量，以及各 Agent 实际删除的会话数量，并刷新当前工作区会话列表。完整发现后仅剩本地记录且所属 Agent 可用的条目直接清理本地记录，不额外探测原生存在性，不受天数限制；置顶、活动、排队和正在查看的记录仍保留。达到时间预算时显示已完成的部分统计，可再次发起清理；未处理项不计为失败，具体规则见[清理会话](sessions.md#清理会话)。

## 阅读步骤

“最近会话”页也提供“主会话 / 子会话”分类，默认主会话，规则与[会话列表](sessions.md#步骤)一致。分类不显示运行或未读徽标，点击只切换列表，不打开会话；运行总数在最近会话页内明确显示。打开记录时，工作区会话列表同步到该会话的实际分类。

1. 先查看用户消息及后续 Agent 文本，再按需要展开工具、命令和文件更改卡。
2. 对计划、审批或问题卡，只使用界面提供的按钮/输入，不要从普通工具文本猜测可回传操作。
3. 长对话滚离底部后使用“回到最新”；需要核对改动时从文件更改卡打开 Diff。

滚离底部时会出现“回到最新”，避免流式内容强制抢走阅读位置。当前浏览器正在查看目标普通会话或托管对话时，通知会自动标记为已读且不弹出；其他浏览器仍能同步看到通知状态。普通会话的主动中断，以及托管对话的主动停止或删除，不会产生终态通知。运行、审批、问题和计划通知在 Server 保留 24 小时，刷新页面或实时连接恢复后会重新出现在通知中心，但不会重复弹出；托管对话只生成 Run 成功、失败或非预期中断通知，不生成审批、问题或计划通知。文件上传和停止提示只属于当前浏览器；文件上传通知出现时直接为已读，不增加未读数，但仍会短暂预览。

“会话与通知”位于主导航“对话”后，PC 和移动端共用一个入口。右上角数字表示未读通知数（超过 99 显示 99+），右下绿点表示有普通会话正在运行。打开时有未读默认“通知”，否则默认“最近会话”；面板打开后不因新通知或全部已读而自动切页，也不因打开就标记已读。“通知”页保留上传任务及普通/托管通知和全部已读操作。桌面面板在左侧入口旁向右展开，移动端沿用顶栏下方辅助菜单；列表可滚动，通知预览靠近入口且不抢占已打开的菜单。最近会话保留普通工作区非终态任务与最近 12 小时内最多 100 条终态任务，不包含托管对话；运行中按启动时间、已结束按完成时间（缺少时最后更新时间）倒序。点击定位原 Node、Workspace 和会话。删除通知不删除最近会话。Node 明确标记的主动停止显示“已取消”，其他中断及无原因的旧记录仍显示“已中断”。

断线重连、从后台切回或窗口重新获得焦点后，如果页面可见且获得焦点，并仍在查看同一个普通会话或托管对话，会重新确认该目标的未读通知并补标已读，无需切换会话。通过顶部导航返回已选中的工作会话或托管对话时，也会补标该目标的未读；其他会话的未读仍保留。点击通知中心或系统通知只标记该条已读，不批量清除同一目标的其他通知。角标以 Server 确认结果更新，已读请求失败时不会直接清空计数，下一次连接或焦点恢复会再次补做。

可使用 `Ctrl+Shift+E`（macOS 为 `Command+Shift+E`）快速打开或关闭会话与通知聚合面板。

**成功标志：** 回复生成时文本在原位置更新，完成后成为一轮完整对话；刷新页面后仍能按原顺序阅读历史。

若出现重复项目或持续不更新，先刷新当前会话；若仍存在，参阅[会话运行排障](../troubleshooting/session-run.md)。

历史中的审批和问题卡只用于回看，刷新后不能再次回答已经结束的旧请求。图片缓存过期或 Node 重启后会显示不可预览提示，而不会继续显示失效图片。
