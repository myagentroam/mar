# 创建、查找与管理会话

## 前置条件

当前工作区已打开，Node 在线且至少一个 Agent 可用。会话列表只显示当前工作区中当前用户有权查看的 Agent 会话。

普通工作会话的执行目录必须是所选 Workspace 的有效根目录或其子目录；独立登记的 Git worktree 使用自己的 Workspace。目录被删除、根路径被替换或链接实际越界时，Node 会拒绝新执行，不会自动切换到其他目录。若排队消息因此暂停，先恢复有效目录，再使用队列的“继续”操作；消息与附件会保留，也可按原操作删除或清空队列。此检查不把工作模式变为宿主文件系统沙箱，也不改变托管对话的隔离目录。

## 步骤

1. 在当前 Workspace 的会话面板点击“新建会话”，或从列表选择已有会话。
2. 初次最多加载 30 个会话；滚动接近列表底部时会自动追加最多 30 个历史会话，搜索结果也按此方式继续加载，不会把新会话放到隐藏页。底部圆环表示正在读取；失败会保留已有会话并暂停自动加载，在底部选择“重试”后继续。
3. 在支持该功能的 Node 上，可在会话栏搜索标题。搜索由 Node 重新查询当前 Workspace 的 Agent 原生会话，因此可以找到尚未加载到浏览器的会话；清空搜索恢复普通列表。
4. 使用会话菜单重命名、置顶或删除。正在运行的会话隐藏删除入口；确认删除期间若会话开始运行，操作不会提交。重命名和置顶仍可使用。
5. 由 Agent CLI 或编辑器创建的历史会话被发现后也会出现在列表；首次发送时 Node 自动验证并激活安全的继续路径。
6. 在会话“更多”菜单选择“定时任务”，填写任务提示词。尚无任务时显示“未配置”，启用开关默认关闭；重复周期和时间只是未保存的表单默认值。需要自动执行时，打开启用开关后保存。简单模式可用时间选择器设置每小时、每日或每周的执行时间；Cron 模式可填写标准五字段表达式，支持数字、范围、列表和步长。任务按 Node 时区执行，无需设置时区。弹窗以昵称或账户名显示通知人；保存后由最后保存的用户执行任务并接收通知。任务通知默认关闭；开启后接收运行完成、跳过和失败提醒，关闭后仅保留最近记录，不发送对应的站内通知、系统通知或离线推送。修改提议仍单独通知。启用后会话自动置顶，列表显示时钟；暂停或删除任务不会自动取消置顶。弹窗可查看下次执行、最近记录和待确认的修改提议；最近记录每页显示 10 条，可翻页查看，翻页不会覆盖未保存的任务内容。

Node 重启后的首次会话加载等待 Agent 原生发现结果，各 Agent 的会话可能分批出现；较慢的 Agent 不影响已发现会话的展示。已有自定义标题会在对应会话被发现后保留，不会先把未发现的历史会话显示为“新建会话”。

仅修改任务提示词、通知设置或保存者，不会推迟已安排的下一次触发。修改时间规则或暂停后重新启用时，才从当前时间重新计算；暂停期间不会补跑。

工作区 Tab 按[未读、活动任务、上次会话的优先级](navigation.md)定位；目标已经打开时保留阅读位置。重复点击工作区树中的当前工作区，或从会话列表、快速打开再次选择当前会话，不会刷新内容或改变正文阅读位置；正在加载时也不会重复请求。需要更新数据时请使用对应的刷新入口。

**成功标志：** 所选会话在标题区显示名称和状态，刷新后仍能从对应 Agent 的历史中重新打开。

## 阅读与运行反馈

同一轮对话可以包含多个可折叠的“工作过程”。公开思考文本、工具和文件操作按实际顺序放在过程中；Agent 正文、审批和提问独立显示。当前过程默认展开，结束后自动收起，手动展开或收起的选择会保留。没有公开思考文本时不会生成空思考卡，思考内容也不代表执行状态。文件详情仍通过原有弹窗查看。

过程状态行上方与折叠的思考行会显示思考预览：优先使用公开摘要，没有摘要时取对应思考首个非空行的首个分句。长内容按可用宽度单行省略，展开思考可读取完整原文；思考预览不代表执行状态。

阅读正文时可在顶部加载更早记录；失败后在原位置点击“重试”，不会清空已读内容。加载完毕显示“已到最早消息”。发送中只表示消息正在提交，不代表 Agent 已开始运行。运行状态来自 Node；没有可展示的具体动作时显示“运行中”，不凭空补写思考摘要。本轮耗时使用 Run 的起止时间，包含同轮等待和续作；缺少可靠时间时不显示，Node 重启后的新一轮重新计时。

## 清理会话

在当前工作区会话列表的“更多”菜单选择“清理会话”，输入 1–365 天（默认 30 天）后确认。活动时间早于所选天数的会话，以及没有有效活动时间、列表显示为 `—` 的会话，都会纳入清理；无时间会话不受天数限制。置顶、运行中、排队、正在重启恢复或正在查看的会话仍会保留。仅有内部记录、未发现原生会话的条目，须由可用 Agent 确认原生会话不存在后才清理。

清理会永久删除符合条件的原生会话，无法撤销，但不会删除工作区文件。完成后弹窗显示实际删除、跳过、失败数量及按 Agent 的删除数量。

## 分享工作会话

在普通工作会话的“更多”菜单选择“分享对话”。有效期可选，留空则永久；创建后展示包含链接和随机六位数字密码的分享文字，点击“复制”即可整段复制。弹窗下方列出已有分享，可以随时复制同样的完整分享文字、打开链接或删除记录。较早版本创建的记录若未保存可恢复密码，首次复制时需补录原密码；验证后不再需要补录，原链接和密码保持不变。

分享页顶部显示会话标题和工作区名称。访客输入密码后进入独立聊天页，不需要工作台账号。登录凭据、匿名标识及首次发送时设置的名称保存在当前浏览器；刷新或重新打开仍可恢复。右侧“参与者”首位显示分享者，其余显示同一会话所有分享链接的在线参与者。同一浏览器的匿名身份和名称跨链接复用。在自己的访客名称旁可编辑显示名称，其他已打开的分享页会同步更新；取消不会更改名称，也不会发送消息。访客名称与消息中的发言者名称一致，不因工作台登录状态合并或隐藏；未设置名称时也显示匿名访客。分享者固定显示账号昵称，无昵称时显示用户名；分享者的绿点仅在其打开分享页时显示，关闭最后一个页面后下线。昵称只用于显示，不用于授权。

分享访问原会话的全部历史与后续消息。访客以分享者身份使用原 Agent 和会话配置，可以发送消息、上传附件、引用文件或技能、排队、插入和打断；多人操作的状态和互斥与多个浏览器打开同一会话一致。分享页不显示模型、思考强度、访问模式、上下文用量及其提示，也没有输入预测或工作区管理区域，文件链接仍支持普通及独立窗口的只读预览，包括 Markdown 和 HTML 渲染。HTML 的可执行脚本及原有风险提示不因只读而改变。

**只把链接和密码交给可信任的人。** 分享者的退出登录不撤销分享；需要停止访问时删除该分享记录。删除或到期立即使对应聊天页失效并拒绝后续读取和发送，但不会停止已经接受的任务，也不收回已读内容；其他分享链接和原工作台不受影响。

## 正常停止后的自动续作

普通 Workspace 的 MAR Agent 支持 Node 收到 `SIGTERM` / `SIGINT`、完成正常退出后再启动时自动续作；正常停止后稍晚手动启动也适用。Node 重新连接 Server 后，会按当前用户权限和模型授权恢复同一原生会话的未完成任务、Goal 与消息队列；原本暂停的队列保持暂停。恢复期间，该会话暂不接受新消息或队列修改。

普通运行的历史会显示“系统重启续作”，不会冒充用户手动发言；活动 Goal 只创建一条目标续作，不叠加普通续作。恢复提示要求 Agent 因系统重启先检查现场，再继续未完成工作：不会恢复旧工具进程、终端、审批、问题或后台 cell，也不保证外部操作只发生一次。排队消息按原顺序重新准备，附件随输入恢复，但原附件预览地址不保证保留。

异常退出、强制杀进程、主机断电、退出交接失败、其他 Agent、托管对话及管理端受控升级不在范围内。用户失权、模型不可用或输入无法重建时，不会绕过检查强行执行；请检查 Node 诊断并手动接手。恢复清单只消费一次，不会在下次启动反复重试。

## 会话提示词（Session Prompt）

在支持的 Node 上，从已有会话的“更多”菜单选择“会话提示词”，输入多行指令并保存；留空保存可清除。最多 20000 字符，仅属于此会话，重新打开或 Node 重启后仍保留。它追加在当前发送者的通用个人提示词和 Agent 专属个人提示词之后，不替代账号设置，也不作为普通消息显示。

修改不打断当前执行，从下一次执行开始生效，包括排队消息、Goal 续作以及 marctl 向该会话发送的消息。marctl 不提供编辑提示词的命令。清除只停止后续注入，不会删除 Agent 对话历史中已有的旧指令；若需完全隔离旧指令，请创建新会话。托管对话不提供此设置。

## 失败排查

- 列表没有更新：先检查当前 Node 在线，再手动刷新当前 Workspace；不要用浏览器整页刷新代替 Node 故障排查。
- 会话无法继续：查看[Agent 与会话控制状态](../concepts/runner-control.md)。
- 删除失败：确认会话没有正在运行，并且当前账户拥有该工作区的使用权限。
- 定时未执行：在定时任务弹窗查看最近记录。Node 重启、会话忙碌、Server 离线或最后保存者失去权限时，本次跳过且不补跑；开启任务通知后，当前通知人会在通知中心收到跳过、失败及运行完成提醒；关闭后仍可在最近记录查看结果，但不会收到这些通知。

## 安全与影响

重命名和置顶只改变 MyAgentRoam 中的显示信息，不改写对话正文。删除会移除对应 Agent 会话，不能恢复；删除前确认不再需要其历史。

定时任务在原会话中以最后保存者身份自动运行，使用执行时的会话 Runner、模型与权限配置。已开始的运行仍属于当次发起人，后续编辑不改变其最近任务归属。定时运行会自动批准工具权限请求，包括第三方 MCP；需要用户提供内容的提问仍需用户回答。普通 Workspace 会话均加载 MAR 定时任务 MCP，可在新对话中直接创建，也可在手动对话中修改当前会话任务的提示词或时间；其他用户通过 MCP 提交的修改须由最后保存者在弹窗确认。工作区会话列表的“已加载 MCP”会将它标记为“执行时注入”，它不是需要单独安装的 MCP。该 MCP 仅管理当前 MyAgentRoam 会话的 MAR 定时任务，不管理项目仓库中的 cron、CI 或其他项目的定时器。
