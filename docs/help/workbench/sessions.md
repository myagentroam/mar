# 创建、查找与管理会话

## 前置条件

当前工作区已打开，Node 在线且至少一个 Agent 可用。会话列表只显示当前工作区中当前用户有权查看的 Agent 会话。

普通工作会话的执行目录必须是所选 Workspace 的有效根目录或其子目录；独立登记的 Git worktree 使用自己的 Workspace。目录被删除、根路径被替换或链接实际越界时，Node 会拒绝新执行，不会自动切换到其他目录。若排队消息因此暂停，先恢复有效目录，再使用队列的“继续”操作；消息与附件会保留，也可按原操作删除或清空队列。此检查不把工作模式变为宿主文件系统沙箱，也不改变托管对话的隔离目录。

## 步骤

声明分组能力的 Node 会在会话列表中显示“主会话 / 子会话”，默认打开主会话。有父会话关联的会话归入子会话，无父关联的会话归入主会话。搜索和翻页只作用于当前分类；切换不会关闭当前对话或中断任务。同一页面内会记住各工作区上次选择的分类，刷新后默认主会话；缺少分组能力时保留混合列表。

分类标签只显示名称和选中态，不显示运行数或未读角标，点击只切换列表、不打开会话；具体会话行继续显示运行和未读。从通知、最近会话列表项或工作区 Tab 打开目标时，会同步正确的主／子分类。

点击或点按对话标题可以分享、重命名，或查看当前会话的会话树、提示词和定时任务（按会话能力显示）。要选择打开位置、置顶、排序或删除，请使用会话列表的“更多”菜单。标题、列表和会话树节点菜单均可**复制会话 ID**；标题栏不直接显示 ID。点击标题栏右侧的会话树图标，或从标题、列表菜单打开树；悬停不会展开。点击树节点默认在 Aside 打开，也可通过节点菜单在主工作面打开。点击树外部、按 Esc 或使用移动端返回可关闭树。

树显示直接上级与递归下级，打开期间通过 Workspace 更新运行中、休眠中和空闲状态，同层会话优先显示活跃分支，再按最近活动时间倒序排列，未知时间排在最后。加载时只显示转圈，不遮暗背景。超过 100 个下级会话时，按此顺序选取并保留必要上级，仍最多显示 100 个并提示截断，活动汇总不受截断影响。

同一会话可以同时在主工作面和 Aside 打开；在一侧打开不会关闭另一侧，重复打开同一位置也不会刷新正文。每个工作区的 Main、Aside 各自保留独立的输入正文、技能标签和引用；同侧切换会话或新建会话不会替换输入，切换工作区后恢复该工作区对应侧的草稿。同一会话在两侧打开时也不共享输入，但仍防止同时重复提交；队列消息的编辑保持绑定原会话。关闭 Aside 会话标签只停止该位置的正文显示，不会结束 Agent 任务、删除会话或关闭主工作面。

普通工作模式下，关闭工作区仍会保留当前浏览器标签的草稿，以便重新打开时恢复。退出登录或登录身份失效会清除该标签保存的输入草稿与队列编辑内容，避免另一账号恢复它们；重要的未发送内容请先另行保存。这不会删除已经发送或已经排队的消息。

每个工作区的 Aside 最多保留一个会话标签。打开另一会话会替换原会话标签，保留 Aside 当前输入，不结束原会话任务；文件、终端等工具标签不受影响。

Agent 操作和来自其他会话的消息收在工作过程内的 [Agent 协作](conversation.md) 组。组内不提供会话快捷跳转。需要查看目标会话、发送消息或停止运行时，从会话列表或会话树打开，仍遵循普通会话权限。

Agent 向已结束或正在停止的父、祖父等祖先会话发送消息或设置 Goal 时，操作会返回 `AGENT_ANCESTOR_NOT_ACTIVE`，不会重新拉起祖先。祖先恢复运行后可以正常发送；用户手动继续会话不受影响。

展开执行记录可查看已有的命令或代码、输出、工作目录、退出码和状态。每次调用各有一条记录。“复制公开记录”复制该条记录已有的公开信息，内容可能被截断；旧版 Node 提供的详情可能较少。

1. 工作区没有可恢复的会话时，主区默认显示新建会话草稿，即使列表已有历史会话也不会自动打开第一条。你可以直接输入，或从列表选择已有会话；新会话在首条消息发送成功后才创建。支持分组时，点击“新建会话”或使用新建快捷键会切到主会话分类。之后手动切换分类不会改变 Composer 草稿。
2. 初次最多加载 30 个会话；滚动接近列表底部时会自动追加最多 30 个历史会话，搜索结果也按此方式继续加载，不会把新会话放到隐藏页。底部圆环表示正在读取；失败会保留已有会话并暂停自动加载，在底部点击“加载失败，点击重试”后继续；重试中只显示圆环。
3. 在支持该功能的 Node 上，可在会话栏搜索标题。搜索由 Node 重新查询当前 Workspace 的 Agent 原生会话，因此可以找到尚未加载到浏览器的会话；清空搜索恢复普通列表。
4. 使用会话列表的“更多”菜单重命名、置顶或删除。正在运行的会话隐藏删除入口；确认删除期间若会话开始运行，操作不会提交。重命名和置顶仍可使用。
5. 由 Agent CLI 或编辑器创建的历史会话被发现后也会出现在列表；首次发送时 Node 自动验证并激活安全的继续路径。

Node 重启后的首次会话加载等待 Agent 原生发现结果，各 Agent 的会话可能分批出现；较慢的 Agent 不影响已发现会话的展示。已有自定义标题会在对应会话被发现后保留，不会先把未发现的历史会话显示为“新建会话”。

会话列表、最近会话和快速打开默认在主工作面打开。点击通知列表里的通知、浏览器系统通知或[工作区标签未读](navigation.md)时，目标已在主工作面就留在那里；只在侧栏打开且侧栏可显示时，就切到侧栏，不替换主会话。桌面会短暂描边提示侧栏会话位置。目标尚未打开或侧栏无法显示时，在主工作面打开，不关闭已有侧栏标签。显式选择「在主工作面打开」或「在侧栏打开」仍按指定位置打开。

重复点击工作区树中的当前工作区，或跳转到已经打开的会话，不会主动刷新内容或重置阅读位置；正在加载时也不会重复请求。需要更新数据时请使用对应的刷新入口。

**成功标志：** 所选会话在标题区显示名称和状态，刷新后仍能从对应 Agent 的历史中重新打开。

## 阅读与运行反馈

首屏或更早历史加载失败时，不会自动反复请求；在正文点击“加载失败，点击重试”即可重新读取，加载与重试中只显示圆环。同一失败不重复弹出消息；重试入口的补充提示保留可用的错误码、详情和请求标识。已建立的实时订阅有有限恢复，页面连接恢复也会重建订阅；这些读取或订阅恢复不会重新执行 Agent 任务。

同一轮对话可以包含多个可折叠的“工作过程”。公开思考文本、工具和文件操作按实际顺序放在过程中；Agent 正文、审批和提问独立显示。当前过程默认展开，结束后自动收起，手动展开或收起的选择会保留。没有公开思考文本时不会生成空思考卡，思考内容也不代表执行状态。文件详情仍通过原有弹窗查看。

过程状态行上方与折叠的思考行会显示思考预览：使用对应范围内最新有效的公开思考记录（摘要或内容），取首个非空行，去除行首标题或加粗格式标记后提取首个分句；较早的摘要不会覆盖后续思考。长内容按可用宽度单行省略，展开思考可读取完整原文；思考预览不代表执行状态。

向上滚动到正文顶部会加载更早记录；新内容接在原内容上方，保留当前正在阅读的消息和视口位置，不自动跳到新页开头。继续上滚即可连续阅读更早记录。首屏加载完成后，如果顶部历史触发点仍在可视区，会自动补载一次并保持原阅读位置，不会连续拉取全部历史。正常状态不显示加载按钮，加载及重试中只显示圆环；失败后点击“加载失败，点击重试”，不会清空已读内容。历史全部加载后不再显示加载或起始提示。发送中只表示消息正在提交，不代表 Agent 已开始运行。运行状态来自 Node；没有可展示的具体动作时显示“运行中”，不凭空补写思考摘要。本轮耗时使用 Run 的起止时间，包含同轮等待和续作；缺少可靠时间时不显示，Node 重启后的新一轮重新计时。

## 清理会话

在当前工作区会话列表的“更多”菜单选择“清理会话”，输入 1–365 天（默认 30 天）后确认。活动时间早于所选天数的会话，以及没有有效活动时间、列表显示为 `—` 的会话，都会纳入清理；无时间会话不受天数限制。置顶、运行中、排队、正在重启恢复或正在查看的会话仍会保留。完整发现成功后，仅剩本地记录且所属 Agent 可用的条目直接清理本地记录，不再额外探测原生会话；不会因此删除未发现的原生内容。

清理会永久删除符合条件的原生会话，无法撤销，但不会删除工作区文件。完成后弹窗显示实际删除、跳过、失败数量及按 Agent 的删除数量。

子会话按自身活动时间独立参与清理，主会话长期使用不影响过期子会话的清理。符合条件的父会话会级联删除全部后代；后代近期活跃、置顶、排队或正在查看不会阻止级联。存在运行中或正在重启恢复的后代时，会保留其父会话。MAR Agent 的级联删除使用原生批量删除能力，统计包含实际删除的全部成员。

清理采用有时间预算的批次。达到预算时，弹窗显示“已完成部分清理”和已完成的实际数量，不把待处理条目计为失败；已知剩余数量时同时显示“待处理”。可再次发起清理处理剩余会话。已开始的删除会先结算，不会返回后继续启动删除；Node 离线或无法取得结果仍会报错。

## 分享工作会话

在普通工作会话的“更多”菜单选择“分享对话”。有效期可选，留空则永久；创建后展示包含链接和随机六位数字密码的分享文字，点击“复制”即可整段复制。弹窗下方列出已有分享，可以随时复制同样的完整分享文字、打开链接或删除记录。较早版本创建的记录若未保存可恢复密码，首次复制时需补录原密码；验证后不再需要补录，原链接和密码保持不变。

分享页顶部显示会话标题和工作区名称。访客输入密码后进入独立聊天页，不需要工作台账号。登录凭据、匿名标识及首次发送时设置的名称保存在当前浏览器；刷新或重新打开仍可恢复。右侧“参与者”首位显示分享者，其余显示同一会话所有分享链接的在线参与者。同一浏览器的匿名身份和名称跨链接复用。在自己的访客名称旁可编辑显示名称，其他已打开的分享页会同步更新；取消不会更改名称，也不会发送消息。访客名称与消息中的发言者名称一致，不因工作台登录状态合并或隐藏；未设置名称时也显示匿名访客。分享者固定显示账号昵称，无昵称时显示用户名；分享者的绿点仅在其打开分享页时显示，关闭最后一个页面后下线。昵称只用于显示，不用于授权。

分享访问原会话的全部历史与后续消息。访客以分享者身份使用原 Agent 和会话配置，可以发送消息、上传附件、引用文件或技能、排队、插入和打断；多人操作的状态和互斥与多个浏览器打开同一会话一致。分享页不显示模型、思考强度、访问模式、上下文用量及其提示，也没有输入预测或工作区管理区域，文件链接仍支持普通及独立窗口的只读预览，包括 Markdown 和 HTML 渲染。只读模式不会阻止 HTML 运行脚本。请仅预览信任的文件，参见 [HTML 预览风险](files.md#步骤)。

**只把链接和密码交给可信任的人。** 分享者的退出登录不撤销分享；需要停止访问时删除该分享记录。删除或到期立即使对应聊天页失效并拒绝后续读取和发送，但不会停止已经接受的任务，也不收回已读内容；其他分享链接和原工作台不受影响。

## 正常停止后的自动续作

普通 Workspace 的 MAR Agent 支持 Node 收到 `SIGTERM` / `SIGINT`、完成正常退出后再启动时自动续作；正常停止后稍晚手动启动也适用。Node 重新连接 Server 后，会按当前用户权限和模型授权恢复同一原生会话的未完成任务、Goal 与消息队列；原本暂停的队列保持暂停。恢复期间，该会话暂不接受新消息或队列修改。

普通运行的历史会显示“系统重启续作”，不会冒充用户手动发言；活动 Goal 只创建一条目标续作，不叠加普通续作。恢复提示要求 Agent 因系统重启先检查现场，再继续未完成工作：不会恢复旧工具进程、终端、审批、问题或后台 cell，也不保证外部操作只发生一次。排队消息按原顺序重新准备，附件随输入恢复，但原附件预览地址不保证保留。

异常退出、强制杀进程、主机断电、退出交接失败、其他 Agent、托管对话及管理端受控升级不在范围内。用户失权、模型不可用或输入无法重建时，不会绕过检查强行执行；请检查 Node 诊断并手动接手。恢复清单只消费一次，不会在下次启动反复重试。

## 会话提示词（Session Prompt）

在支持的 Node 上，从已有会话的“更多”菜单选择“会话提示词”，输入多行指令并保存；留空保存可清除。最多 20000 字符，仅属于此会话，重新打开或 Node 重启后仍保留。它追加在当前发送者的通用个人提示词和 Agent 专属个人提示词之后，不替代账号设置，也不作为普通消息显示。

修改不打断当前执行，从下一次执行开始生效，包括排队消息、Goal 续作以及 marctl 向该会话发送的消息。也可用 [marctl 查看、设置或清除提示词](../operations/marctl.md#持久指令与审批)。清除只停止后续注入，不会删除 Agent 对话历史中已有的旧指令；若需完全隔离旧指令，请创建新会话。托管对话不提供此设置。

## 失败排查

- 列表没有更新：先检查当前 Node 在线，再手动刷新当前 Workspace；不要用浏览器整页刷新代替 Node 故障排查。
- 会话无法继续：查看[Agent 与会话控制状态](../concepts/runner-control.md)。
- 删除失败：确认会话没有正在运行，并且当前账户拥有该工作区的使用权限。
- 定时未执行：在[定时任务](#定时任务)中查看该次执行记录。

## 安全与影响

重命名和置顶只改变 MyAgentRoam 中的显示信息，不改写对话正文。删除会移除对应 Agent 会话，不能恢复；删除前确认不再需要其历史。

## 定时任务

点击“工作”旁带勾的日历图标打开**定时任务**，或从已有会话的菜单进入同一页面并筛选该会话。**我的定时**只显示自己创建且仍有权访问的任务；**全部定时**也显示有权查看的其他任务。两页都可以按工作区筛选，列表在同名工作区旁显示节点。任务卡片每页显示 20 条：桌面端可点击页码切换，移动端滚动到底部会自动加载下一页。每张任务卡片显示该任务的下次执行时间。离线节点可能只显示上次同步的任务摘要；编辑和查看执行记录需要节点在线。

**会话定时任务**即使为空也显示当前会话名称。点击**返回全部定时**回到全局列表；从会话范围新建时，执行节点、工作区和运行会话不可更改。在定时页点击指向会话的通知，会直接退出定时页并显示该会话。

1. 点击**新建定时**，依次选择在线节点、工作区和运行目标。可以复用已有会话，也可以选择**每次新建会话**，并指定 Agent 和固定模型。选择模型后会带入该模型的默认推理强度，可在模型支持时调整。已有会话使用触发时的会话配置。定时不适用于托管对话。
2. 填写任务名称和提示词。在**执行时间**中，每个时刻单独添加一行，选择**仅一次**、**每天**、**每周**或**每月**。选仅一次时，节点会建议最近可执行的日期，你可以修改。每周可多选星期，每月可多选几号；没有 31 日的月份会跳过。多行时间命中同一分钟也只执行一次。不同时间需要不同提示词时，请新建独立任务。
3. 按界面显示的 Node 时区检查接下来几次触发并保存。任务由创建者的账号执行，后续编辑不会变更执行人。需要时开启运行结果通知；默认关闭，关闭后仍保留执行记录，修改提议仍单独发送通知。

仅一次的时间可以开启补跑，并设置最多等待多少分钟；新任务默认关闭补跑。从旧版时间设置升级时，原任务会暂停，需重新设置执行时间；任务和执行记录仍保留。

点击在线任务卡片，可在当前列表打开只读详情。点击已绑定的会话名称，可打开对应会话。离线卡片仅展示摘要。点击**编辑**可修改自己创建的任务。点击卡片上的**执行记录**，打开该任务的记录弹窗，不离开任务列表。二级菜单中的**执行记录**则汇总所有有权访问的任务，可按工作区筛选。桌面端在表格右下角切页，移动端滚动到表格末尾自动加载更多。展开单条记录可查看触发时的提示词与已记录的实际起止时间。若有权限读取原始运行，详情还会显示对应 Run 的 ID 和状态，并可打开运行所在会话。仅编辑名称或提示词不会重新排期；修改时间或恢复启用才会重新计算。指定日期用完时显示**排期已结束**，不代表每次运行都成功。

已有会话有启用且仍有后续触发的任务时会置顶并显示定时图标。暂停、排期结束或删除任务不会自动取消置顶。暂停保留执行记录，删除任务会一并删除记录；若还有正在处理的触发，可先暂停任务，再等该次触发结算。删除目标会话会暂停关联任务并标记需要重新绑定，不会自动改为每次新建会话。

定时没有执行时，先查看该次记录。周期触发遇到会话忙碌或服务不可用可跳过，不批量补跑；指定日期的触发可在设置的时限内等待（0–60 分钟，新任务默认 0，即不等待）。任务仍按创建者当前权限执行，失权不能通过等待绕过。“结果未知”不表示一定未执行；检查运行和外部结果后再决定是否手动重做。

定时运行会自动批准工具权限请求，包括第三方 MCP，Agent 沙箱和主机限制仍生效；需要输入的问题仍需用户回答。普通 Workspace 内，MAR Agent 优先使用内建 `marctl` 技能；未提供该技能时或使用其他支持的 Agent，可用内建 `mar_schedule` MCP 列出、读取、创建、修改当前会话的定时任务和查询触发记录，无需额外安装。更新必须指定任务及其当前版本；修改其他人的任务会生成提议，由创建者确认。要在当前授权 Workspace 中跨会话管理任务，参见 [用 marctl 管理定时任务](../operations/marctl.md#定时任务)。这些工具不管理系统定时器或 CI。
