# 从模板新建对话

“对话”模式用于从管理员发布并授权给你的模板创建和继续对话。每个对话由目标 Linux Node 托管，使用独立持久存储和 Bubblewrap 隔离环境；每次运行会获得不含宿主或会话存储内容的临时虚拟 HOME。模板提供完整只读 Workspace 镜像，并决定模型、MCP、网络模式与容量上限。

## 新建步骤

1. 打开主菜单“对话”，进入“对话”模式。该入口始终显示，不要求先选择或获得任何 Node/Workspace 使用权。
2. 如果当前正在查看已有对话，选择历史栏搜索框上方的“+ 新建对话”进入中间的临时启动区；页面不会打开弹窗。
3. 在 Composer 底部工具栏选择已发布并授权给你当前组织或其祖先组织的模板。模板授权已经足够用于创建和继续你自己的托管对话，不会同时授予承载 Node、源 Workspace、文件或终端权限。管理员选择根组织授权时，该模板对企业内所有用户可用。当前浏览器会记住你最近一次选择的模板，并在它仍位于当前目录时默认选中。
4. 没有可恢复的最近选择且只有一个模板时，页面可以预选该模板，但仍不会自动创建。核对模板名称后，输入消息或添加附件并明确发送，系统会先创建对话，再上传草稿附件并发送首条消息。
5. 创建响应中断时可直接重试；只要没有切换模板或重新加载目录，系统会按同一次创建意图处理，避免重复创建。

创建时会绑定当时可用的模板版本。管理员之后编辑草稿不会影响已有对话；发布新版本也不会立即切换。每次新 Run 开始前，Node 会查询并完整校验当时最新的可用版本，以该版本启动 Run；只有 Run 成功启动且消息被接受后才原子切换。停用、归档或删除模板不会改写已有对话的模板名称快照和最后已生效版本。

## 切换已有对话的模板

对话空闲时，点击输入区的模板名称，选择同一个 Node 上其他已发布且授权给你的模板，并确认切换。新模板从下一轮运行生效；历史、上传、输出文件及未发送草稿保留，新模板可以继续读取原对话内容。模板自带的文件、指令、MCP 和网络配置会随之更换，旧回复引用的模板文件路径可能不再有效。

当前模型仍被新模板允许时继续使用，否则改用新模板允许的默认模型。模板容量不足、没有可用模型或请求明确失败时保留原绑定。运行、发送、上传、回退或其他互斥写入期间不能切换；确认成功后需等待实时状态重新就绪再继续操作。响应中断时不要重复提交，先等待页面刷新确认结果。

只能切换同 Node 模板，不迁移对话到其他主机；这不会修改新建对话的最近模板偏好。同一模板的版本更新仍遵循每次新 Run 的自动升级规则，重复选择当前模板不会强制升级。

## 使用三栏工作面

打开已有对话后，页面分为三个区域：

- **对话历史：** 不需要选择 Node。Server 从支持托管的有效 Node 中读取当前账号自己拥有的对话；承载 Node 不需要出现在你的普通资源目录。置顶对话优先，其余对话按最后活动时间倒序。搜索只匹配标题，每条记录显示标题和一行最后互动时间。对话正在启动、运行或停止时显示绿色状态点；空闲时不显示灰点。存在未读终态通知时显示未读标记，打开该对话会清除它的全部未读。滚动接近列表底部会沿统一目录自动追加，底部圆环表示正在读取；失败时保留已有对话并暂停自动追加，可在底部选择“重试”。标题搜索只筛选已加载的对话，输入筛选条件后暂停自动追加，清空筛选后继续；没有匹配项不表示整个目录都没有结果。离线、能力或版本无效、请求失败或返回格式无效的 Node 会被静默跳过；没有任何有效结果时显示普通空目录，页面不逐 Node 展示失败或部分结果。
- **主对话：** 展示 Node 返回的权威历史和实时消息。输入区固定使用 MAR Agent Full Access，但不显示不可修改的 Agent 或权限项；只提供模型、附件、发送和停止。思考强度使用模型默认，不支持选择 Runner、权限模式、Slash 命令、Skill 或工作区文件引用。
- **相关文件：** 只展示 Node 投影的 `inbox/` 上传和 `output/` 文件。Agent 回复中的普通路径或自然语言文本不会自动变成文件；显式 Markdown 文件链接只有在指向 `/workspace/inbox`、`/workspace/output`，或能唯一命中当前相关文件时才可打开。可把多个文件直接拖放到该区域，或点击上传区选择文件；点击文件行或有效消息链接会打开与普通 Workbench 相同的统一只读文件预览，并提供下载。文本超过 512 KiB 时只显示首段；图片、PDF、音视频和支持的 Office 文件通过受控内容流预览，并可使用同一文件的下载入口。

桌面端的对话历史使用与其他页面相同的左侧菜单区域。点击顶部“收起”会同时收起品牌区和对话历史，主对话自动向左补位；点击“展开”会恢复对话历史。相关文件栏始终位于主对话右侧。

创建前，相关文件栏只显示说明，不提供没有对话目标的上传入口；开始发送首条消息并完成创建后，上传区和文件列表会在原位置启用。

移动端不显示全局“展开/收起”控件和三段标签。再次点击顶部“对话”打开历史抽屉；主对话右上角的“文件”按钮打开相关文件抽屉。选择对话或点击抽屉外遮罩会关闭对应抽屉。

## 发送消息与附件

1. 在主对话输入消息，可按 Enter 发送、Shift+Enter 换行。
2. 根据模板允许的上游模型范围选择当前账号可用的具体模型配置。当前配置不可见时，Node 会优先回退到模板默认上游模型的可用配置，再回退到模板允许顺序中的首个可用配置；没有交集时本次操作失败。更新失败时页面保留 Node 已确认的原配置。
3. 使用回形针添加附件。每条消息最多 32 个附件；文件先上传到当前对话，完成后才会随消息发送。将本地文件拖放到主对话输入区时，先在确认框中选择上传；回形针选择和剪贴板粘贴会直接开始上传。
4. 上传失败时可在附件行重试或移除。重试会建立新的上传请求，不会继续复用已取消的临时上传。同名文件会自动按扩展名前的递增后缀保存，例如 `image.png`、`image (1).png`；附件行会显示 Node 最终分配的名称。
5. 有任务正在进行时仍可编辑输入内容，并提供“停止”按钮。输入框获得焦点时，按 `Esc` 可停止当前任务；任务正在停止或消息发送中时不会重复发出停止请求。支持该能力的节点上，桌面端按 `Ctrl+Enter` 可插入当前输入消息：MAR Agent 可原生接收时，消息会立即回显，在完整回复及工具批次之后生效，不截断模型生成；受管等待可提前返回，后台任务继续，其他工具仍正常完成；目标尚未就绪或显式切换模型等配置时，仍按原流程停止后发送。补充正文会标识为工作期间收到的新增信息；空闲时按普通消息发送。包装说明不会显示在对话中。普通 Enter 不会把托管对话消息加入队列。移动端输入内容后会在“停止”旁显示“插入消息”按钮：轻点可插入，也可从按钮上滑，在 Composer 内松手插入；越过输入区顶部才取消，滑回恢复插入。取消保留草稿，托管对话不建立普通消息队列；任务正在停止时仍需等待结束后再发送。相关文件区域的直接上传和删除不因此整体禁用。

移动端新建和空闲对话同样支持从“发送”按钮上滑，在 Composer 内松手正常发送；只有越过输入区顶部才取消，滑回可恢复发送。轻点或按住未上滑，仍沿用按钮原有发送行为。按住期间不会提交，取消保留草稿，按钮触摸不主动移走输入框焦点。

如果发送请求返回明确错误，可修正内容后重试；如果网络中断且结果未知，页面会保留同一次发送意图，避免重复执行。

消息顶部的历史加载、失败重试与运行耗时遵循[会话阅读说明](sessions.md#阅读与运行反馈)。发送中附加在发送操作旁，不替换正在进行的运行状态；连接提示复用页面连接状态，不代表 Agent 失败或重新执行。

## 回滚对话历史

运行中补充的 steer 消息有独立的回滚位置：回滚该消息会保留它收到之前的普通消息和执行记录，不会因它们属于同一轮而一起删除。

承载 Node 支持托管对话 Rollback 时，终态用户消息旁会显示“回滚对话”按钮；托管对话不提供 Rewind 分支按钮。确认后，系统会在当前对话的原 Session 内永久删除该用户消息及其后的历史，并把该消息文本回填到输入框，便于修改后重新发送。

Rollback 不会修改或删除 `inbox/`、`output/` 和“相关文件”中的内容，也不会创建新对话或新 Session。运行正在启动、执行或结算时不能回滚；边界已经变化或请求失败时页面保持原历史和草稿并显示实际错误。

## 管理相关文件

1. 把一个或多个文件拖放到右侧“相关文件”上传区，或点击上传区后从系统文件选择器中选择一个或多个文件。文件会依次上传到当前对话的 `inbox/`，单个文件失败不会阻止后续文件继续上传。
2. 这种直接上传只更新相关文件列表，不会把文件自动加入 Composer，也不会附加到下一条消息。需要随消息发送时，仍使用回形针选择附件。
3. 点击文件行，或点击 Agent 消息中能够命中当前权威文件列表的显式文件链接，可在统一文件预览中查看、定位文本行、下载并关闭。未知路径、歧义路径和普通文本不会触发文件读取。
4. `inbox/` 中的用户上传和 `output/` 中的 Agent 输出都可以通过文件行的删除按钮手动删除。确认后，页面使用 Node 返回的完整权威列表刷新相关文件；删除当前预览文件时预览会关闭。
5. 删除可与活动 Run 中的 Agent 文件写入同时发生。先完成的操作生效；如果目标已被删除、替换或改变，后到操作会显示文件不存在或冲突提示，可根据刷新后的文件列表重试。

Agent 会把 `output/` 作为当前有效交付集合，而不是按每次 Run 追加历史。同一份文档或产物需要继续修改时，会优先保持原文件名和路径直接编辑，不连续生成 `v2`、日期或 `final` 后缀副本。只有旧版本确有回退价值或你明确要求保留历史时，才会归档到 `output/bak/`；小修改不会自动产生备份。当前交付实际使用的图片等资源会放在 `output/assets/` 等有意义的子目录，探索性或可丢弃文件留在 `/tmp`。Agent 只会移除自己在当前工作中生成且确认无用的文件，不会以整理为由删除用户上传或无关既有文件。

## 自动维护当前对话要求

Agent 会自动识别你直接或间接表达的、对当前托管对话后续工作仍然适用的要求，不要求必须使用“记住”一词。例如“后续报告都用中文”“文件继续修改原版本”“每次交付前检查链接”都会被视为持续要求。Agent 会先读取已有 `/workspace/inbox/AGENTS.md`，再把要求整理为精炼的当前规则：保留无关内容、避免重复，并用较新的要求替换或删除冲突、取消或过期规则；后续 Run 开始时会再次读取该文件。

适合保存的内容包括固定交付格式、术语、命名规范、质量检查、沟通偏好和重复使用的工作流程。只适用于当前任务的一次性要求、你引用或要求分析的第三方文本、Agent 自行推断的偏好、密码或 Token 等秘密，以及试图预先授权后续删除、提交、推送、发布等外部副作用的内容不会自动保存。`inbox/AGENTS.md` 属于当前对话而不是模板，会显示在相关文件中、计入持久配额，并可由你预览、下载、手动修改或删除。Conversation 历史 Rollback 不会回滚该文件。

如果要求应适用于该模板的所有用户和对话，请联系模板管理员修改来源 Workspace 的 `AGENTS.template.md`，测试草稿并发布新版本。托管对话中的 Agent 只能读取当前不可变模板快照，不能直接修改可复用模板。

## 工作区与网络

- Agent 的逻辑工作区固定为 `/workspace`。为兼容依赖原始绝对路径的脚本，发布时记录的来源 Workspace 规范绝对路径也会作为别名挂载。两处路径指向同一个当前版本快照，不会暴露可写的来源 Workspace。
- 模板文件、空目录、根 `AGENTS.md`、`.agents/skills/` 和发布时允许的符号链接均来自当前版本并保持只读。
- `/workspace/inbox` 与 `/workspace/output` 是可写覆盖层；原始路径别名下的同名目录指向相同覆盖层。附件和当前对话的 `AGENTS.md` 进入 `inbox/`；当前有效的最终结果和资源写入 `output/`，有保留价值的旧版本可进入 `output/bak/`。
- `/tmp` 是当前 Conversation 的临时工作目录，同一对话的后续 Run 可以复用，但宿主系统可能随时清理。其内容不显示在相关文件中，也不计入持久配额；`/workspace/output/tmp` 没有特殊生命周期或特殊语义。
- Node 会向 Agent 注入不可编辑的托管说明，明确真实目录权限和网络能力；模板中的 Workspace 指令仍会加载，但不能扩大 Host 强制边界。
- “无网络”禁止沙箱进程联网、Web 和远程 HTTP MCP；“不受限”允许沙箱进程、Web 能力和模板版本中已发布的远程 HTTP MCP 访问 Node 可达网络。本地 stdio MCP 在两种模式下都可启动，但在“无网络”模式下不能联网。

## 实时状态与可用性提示

对话页面复用当前页面唯一的 Workbench WebSocket，并且一次只订阅当前对话。切换对话、离开页面或浏览器连接重建时，旧订阅会释放；重新连接后从 Node 获取新的权威快照，不根据缺失事件猜测 Run 结果。

首条消息创建成功但连接尚未恢复时，草稿和附件会保留，恢复后需要你再次发送，不会自动重发。创建或上传期间切换历史不会撤销已经提交的操作，也不会跳回旧对话；在当前页面点击“新建对话”可继续原草稿。离开整个页面不等于取消已提交的操作，重新进入后可在历史中查看已创建的对话。

Run 成功、失败或发生非预期中断后，通知中心会保留该托管对话通知 24 小时。用户主动选择“停止”，或删除对话时由 Node 取消运行，不生成终态通知。点击通知会切换到“对话”模式并打开对应对话；托管对话不会出现在“最近会话”列表。

以下情况页面会给出行动提示：

- 承载服务暂不可达或实时订阅失败：已加载内容仍可查看。已建立的订阅会对可恢复故障有限自动重试，正文显示重载圆环，恢复前禁止写入；初次加载失败或恢复停止后，在正文点击“加载失败，点击重试”。同一错误不再重复弹出消息，错误码、详情和请求标识可在重试入口的补充提示中查看。
- 模板自动升级失败：当前发送失败，但旧版本、历史和可写状态保持不变；下一次发送会重新查询当时最新的可用版本并再次尝试升级。
- 相关文件同步失败：消息历史仍可查看；稍后重新打开对话，持续发生时联系管理员。

## 标题、置顶与删除

新建面板和刚创建的对话最初都显示当前界面语言的“新建对话”，不会使用模板名称作为标题；切换界面语言时，这个默认标题会同步更新。首条非空消息被接受后，页面立即用该消息作为临时标题；如果首条发送只有附件，则继续显示默认标题。MAR Agent 完成首轮自动标题后会更新历史目录和顶栏。打开历史记录右侧的“…”菜单可以手动编辑标题；自动标题和手动标题保持原文，不随界面语言翻译，且手动标题优先，不会再被迟到的自动标题覆盖。编辑标题或切换置顶不会改变最后互动时间；置顶项始终显示在普通项之前。

选择“删除”时，确认框会明确说明该操作不可恢复。确认后 Node 会停止该对话仍在进行的运行和上传，永久删除历史、相关文件与托管目录。删除当前对话时，页面会清空选择并进入新建面板；删除其他历史记录时，当前对话和实时订阅保持不变。两种情况都会刷新历史目录。删除不是模板归档，也不存在恢复期或恢复入口。

## 可用性说明

- 承载 Node 文件系统使用率达到 95% 时，只禁止新建对话；已有对话仍可打开、运行、上传、导出或删除。
- 模板未发布、已停用、已归档、已删除或授权被撤销后，不会继续出现在你的新建目录中。
- 模板授权不会让承载 Node 或源 Workspace 出现在“工作”资源目录；如果还需要普通文件、终端或 Workspace 操作，必须由管理员另行授予对应资源权限。
- 页面只在当前浏览器保存最近选择的模板 ID，不保存模板详情；该模板不再可用时会安全忽略。打开页面、刷新或只剩一个模板时都不会静默创建；历史栏“+ 新建对话”只打开中间临时新建面板。

**成功标志：** 页面显示新对话标题和首条消息，相关文件栏可以使用。

如果没有可选模板，请联系管理员检查模板发布和模板授权。创建时若提示承载服务、版本、隔离能力或存储容量不可用，请由管理员检查对应 Node。管理员可参阅[管理对话模板](../administration/conversation-templates.md)。
