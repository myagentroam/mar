# 发送消息与使用 Composer

页面底部的消息输入区（Composer）用于选择 Agent 配置、输入消息、引用文件和管理队列。

## 前置条件

已打开会话。对于由外部 Agent 发现的历史，首次发送会自动验证继续路径；若验证失败，不会创建 Run。

## 步骤

1. 选择 Agent、模型、思考等级和权限；只会显示当前 Node 确认可用的选项。切换模型时，思考等级会自动切换为目标模型的默认等级，之后仍可手动选择该模型公开的其他等级。
2. 输入消息。默认 Enter 发送；Shift/Alt+Enter 换行，具体快捷键见[键盘快捷键](../reference/keyboard-shortcuts.md)。
3. 运行中按 Enter 发送的消息会进入队尾；按 `Ctrl+Enter` 可优先补充当前消息。Node 根据实际状态决定投递：MAR Agent 的当前执行可接收原生补充时，消息会立即回显，并在完整回复及工具批次结束后生效，不截断模型生成；受管等待可提前返回，后台任务继续，其他工具仍正常完成；其他 Agent 或配置不兼容时，仍沿停止后优先发送流程处理。补充正文会标识为工作期间收到的新增信息；空闲时与普通发送一致。包装说明不在消息中显示，附件和引用仍按原规则处理。
4. 点击停止会立即进入停止中状态并暂停本会话队列；确认后再继续或调整队列。
5. 输入 `/` 可选择当前 Agent 支持的命令，或在「技能」分组中选择当前工作区已加载的技能；点击命令或在菜单光标位于匹配命令时回车会执行命令。未知 `/xxx` 输入作为普通消息发送；已支持的 Slash 命令也可能接受参数，例如 `/goal <目标>`。选中的技能显示为正文上方的标签，不会立即发送；点击标签关闭图标可以删除。正文已经为空且光标位于开头时，按 Backspace 会从后向前删除技能标签。正式发送时，所选技能按选择顺序作为资源输入传给 Agent，不在发送后的消息中回显。`@` 选中的文件与目录也采用可删除标签和相同的隐藏回显规则；实际上传附件仍显示文件列表。不支持的命令不会显示。
6. 在“设置 → 快捷提示词”创建短语和提示词后，输入 `#短语` 可筛选并插入提示词正文。匹配忽略大小写，完全匹配排在前缀匹配和包含匹配之前；同级保持原顺序。默认选中首项，桌面端按 Enter 可插入。选择后只替换当前 `#短语`，不会自动发送，也不会移除其余输入或附件。

粘贴普通文本时只保留纯文本格式，并可使用 `Ctrl/Command+Z` 整次撤销。达到 100 行或 10000 字符的长文本会在进入输入框前自动转换为 TXT 附件，以避免大段日志或代码导致页面卡顿；转换不会覆盖输入框原有内容，发送前仍需填写消息正文。

已上传但未发送的附件保留 1 小时；超过时间后需重新添加。

**成功标志：** 空闲时发送的消息立即开始并出现在对话中；运行中发送的普通消息先出现在输入区上方的队列，真正开始执行后才进入对话；`Working` 标签反映当前任务。

桌面可拖动队列项调整顺序；移动端长按队列项，在菜单中选择上移或下移。

点击队列项的“执行”（英文为 **Steer**）时，Node 重新判断实际运行状态：工作期间按温和的新增信息（steer）优先投递，空闲时普通发送。使用最新保存的正文，已有 steer 不重复包装；页面仍只显示正文和资源信息。自动按队列顺序执行不会因此变为 steer，目标激活和内部续作等特殊输入保留原语义。

## 输入预测（Prompt Tab）

Prompt Tab 是手动触发操作，Composer Prediction（输入预测）用于根据当前会话和草稿意图生成完整指令，也支持空草稿下的自动预测。输入框下方状态条显示待触发、生成中或预测已就绪，并提供对应快捷键和操作；生成中显示动效，遵循系统减少动画设置。

管理员先在 **管理 → MAR Agent 模型 → 高级 → Prompt Tab** 配置模型和思考强度。全局能力默认开启，但未配置模型不会调用，也不会回退到会话主模型。在 **设置 → 外观（Appearance）** 开启“输入预测”；没有已保存偏好时默认开启，仅支持工作模式；已保存的关闭选择仍保持关闭。下拉框只有“关闭 / 开启”，选择立即生效并保存在当前浏览器；不上传或跨浏览器同步此偏好。

输入框获焦、浏览器处于前台时，快速按两次 `Tab`（约 300ms 内）请求，也可点击“生成”。空输入框在 placeholder 显示下一条消息建议；已有草稿时将草稿作为意图提示，灰字预览完整的新指令，采用前不修改原文。按 `Tab` 或点击“采用”整体替换草稿，之后仍需自行发送；可用原生撤销快捷键恢复原稿。选区和光标位置不影响生成；输入法组字和已打开的 Composer 菜单不触发预测。

生成中单按 `Tab` 即可取消；`Esc` 取消当前预测，不停止 Agent。已有候选旁有“取消”按钮；编辑正文或主动取消会清除候选，离开输入区域、窗口失焦或切回页面不会自动清空候选。候选到期、切换资源或权限失效时仍会清除。输入框始终拦截普通 `Tab`，即使未启用或暂不支持预测也不会丢失焦点，`Shift+Tab` 保持原行为。

草稿为空、浏览器页面可见且获焦、Node 支持自动预测时，当前会话按以下规则生成：

- 进入当前会话：停留约 1 秒后自动检查，无需输入框聚焦，执行中和已结束均可。快速切走取消本次检查；历史仍在加载时，就绪后检查，不再额外等待完整的 1 秒。
- 新的 Agent 公开回复：收到回复时输入框已聚焦，发起前仍需聚焦；失焦收到的回复不会伪装成之后的新回复事件。
- 当前轮次结束：无需输入框聚焦。页面在后台时不请求，已收到的结束事件可在返回前台后处理。
- 输入框从失焦变为聚焦：执行中和已结束均检查；已有覆盖最新上下文的有效候选或在途请求时复用。

重叠信号合并并限频，持续消息不重置进入会话的等待。每次进入只做一次检查，不同会话不继承上一会话的请求冷却。生成中遇到符合条件的新上下文，完成后至多补一次刷新，不并发打断；刷新期间保留仍有效的旧候选，新结果就绪后替换，不改动草稿或抢焦点。新回复或轮次结束不会因已有旧候选而跳过。历史加载只建立基线，不重放旧事件；先聚焦、后加载完成不会丢失进入检查。开始下一轮撤销上一轮尚未发出的结束事件，不取消当前会话的停留或聚焦检查。手动生成、编辑和取消清除本次待处理自动意图，取消按钮回焦不会立即重试；后续符合条件的新事件仍可触发。停留延迟指开始生成的时机，不保证届时已有候选。

工作模式的四种 Runner 共用此能力；托管对话不支持输入预测。Agent 执行中也可以手动请求，不必等待完成。请求会将草稿、当前对话、有界执行快照及获授权的工作区历史用户消息发送给配置的预测模型；历史参考不按作者筛选。Node 使用有界内存缓存，参考刷新不会调用模型；实际模型消耗计入发起用户的输入预测用量。请在采用前检查建议，不要把建议当成已完成工作的事实。

各 Node 在自身数据目录的 `prompt-completion/` 保存按 UTC 日期分片的本地分析记录，包含输入草稿、有界上下文、预测输出、状态及耗时；最多保留当天及前六天。不上传 Server，也不写入会话历史。这些文件可能包含敏感正文，请按私有数据管理。

候选以你向 Agent 发消息的角度表达请求、问题或调整重点，而不是 Agent 汇报自己的计划。手动“生成”会要求一条非空候选，空草稿或任务已完成也会生成；后续不明确时优先给出相关的只读核验或澄清问题。自动预测仍可不提供建议。每次预测只进行一次生成调用，用户视角与任务语义由提示词引导，不追加独立模型复审或代码语义过滤。Node 仅校验输出结构、完整性及有界长度和字符。手动输出不符合结果契约或不完整时会明确报生成失败，不用固定文案伪造候选。采用前仍需自行确认候选内容。

每次触发都会生成新的预测，不复用上一次候选。Node 缓存的是已加载的参考会话，刷新周期到期后在使用时更新，避免每次重新加载。生成期间，对话消息、Goal、队列或运行状态变化不会打断预测；下一次请求使用新状态。

支持该上下文能力的 Node 会参考本页最近三分钟查看的文件和 Diff，以及已有 Goal、待办/待答和队列状态。文件片段由 Node 复核权限及版本；无法确认的内容省略，Diff 仅作为浏览元数据。浏览不是修改授权。运行中侧重干预建议，完成后侧重下一步，未知状态不当作已完成。

自动预测无合适候选或请求失败时静默恢复待触发状态，不弹通知、不显示无候选提示，也不自动重试。手动生成保留明确反馈；旧 Node 意外返回空结果时，“暂无合适的预测”仅短暂显示。

若入口不可用，检查个人开关、Node 版本（至少 0.10.21）和能力、模型/凭据及资源权限。配置位置和权限说明见 [MAR Agent](../runners/mar-agent.md)。

## 目标

### 启动前须知

目标模式支持 MAR Agent、Codex、Claude Code 和 OpenCode 跨轮持续执行，自动续作不限制轮数。**进入模式会清除尚未执行的普通队列。MAR Agent 保留当前 Auto / 完全访问档位；其他 Agent 切换到各自免确认权限，结束或移除目标后不会自动恢复。** 请先确认目标、目录和权限边界，完成后在 Composer 手动改回需要的权限。

`/goal` 采用 MAR 兼容语义，由 Node 为四种 Agent 统一管理，不等同于 Codex 原生 Goal。裸命令进入待输入状态，`/goal <目标>` 设置或编辑目标，`/goal --clear` 移除目标，不提供原生 Goal 的暂停、恢复或预算控制；当前受管 Codex 执行中新建并完成的原生 Goal 也会结束此目标。

| Agent       | 目标模式使用的权限 |
| ----------- | ------------------ |
| MAR Agent   | 保留当前档位       |
| Codex       | 完全访问           |
| Claude Code | 跳过权限确认       |
| OpenCode    | 自动批准           |

### 启动与查看

1. 执行 `/goal`，输入区出现待输入的“目标”标签。
2. 发送下一条消息作为任务目标。启动后标签隐藏，队列区域显示“目标”标题和目标行；再次执行 `/goal` 只提示已处于该模式。
3. 悬停或聚焦可查看过长目标的完整提示；选择“查看”打开完整目标、已执行轮次数和目标修订。

首次执行或更新目标后的重新启动会在会话中显示 `Goal Start`，紧接下一行显示当次完整任务目标；自动续作仅显示 `Goal Continue`，不重复目标。续作或等待失败重试期间处理时长继续累计。
目标从首次启动起累计墙钟耗时，编辑目标不重新计时；该耗时包含等待和重试，不等于模型或工具的实际执行时间。Agent 主动完成或最终阻塞时会取得截至状态更新时的耗时，并应在当前轮总结工作结果、验证和遗留问题；后续总结回复和运行收尾不计入这次统计。Runner 自动失败阻塞时可能无法继续生成总结。

### 干预、更新与退出

| 操作            | 影响                                                               |
| --------------- | ------------------------------------------------------------------ |
| Enter／发送按钮 | 将消息加入队尾，目标结束且当前轮收尾后才按顺序执行，不提前修正目标 |
| Ctrl+Enter      | 停止当前执行后优先发送，保留其他排队消息、不替换目标               |
| 编辑 → 更新     | 修改目标，停止当前轮次并立即按新目标开始；“取消”放弃编辑           |
| 移除            | 退出目标模式并停止自动续作，**不会停止当前正在执行的轮次**         |
| 停止运行        | 中断当前运行并同时移除目标，无需再次执行“移除”                     |

普通排队消息不会插入目标的自动续作、续作准备或失败重试间隙。目标完成、最终阻塞或被移除后，等待当前轮收尾，再执行普通队列；主动停止仍会暂停队列。需要立即干预时，使用 `Ctrl+Enter` 或队列项的“立即执行”，其他普通排队消息继续等待目标结束。

目标完成、连续三轮正常结束但没有工具活动，或最终阻塞后会自动退出。连续空转按完成收口并停止续作，但这不保证目标已实际达成；请根据 Agent 的结果核实。普通 Workspace 中，MAR Agent 的目标可随[正常停止交接](sessions.md#正常停止后的自动续作)恢复，保留原目标、计时与轮次；其他 Agent、托管对话和异常退出不支持此恢复。不要将页面关闭、移除目标或重启后的空闲状态理解为目标已完成。
移除或停止运行成功时，界面根据 Node 返回的结果显示状态、截至操作确认时的累计耗时及已开始轮次；这些操作不会额外启动 Agent 来生成总结。尚未输入目标时没有可统计的耗时。

## 失败排查

- 发送按钮禁用：检查是否处于只读外部会话、Node 离线或保存的模型配置已经不可用。
- 出现 `SESSION_INVALID`：刷新会话后重新选择当前有效模型/配置；若持续出现，参阅[Agent 排障](../runners/runner-troubleshooting.md)。

## 发送前检查

- 确认模型、权限档位符合本次任务；权限越高不等于一定更适合。
- 检查 `@` 引用和附件是否只包含需要的材料。
- 长任务在运行中应使用队列或停止后优先发送，避免重复消息启动多个相同任务。
