# @ 引用文件、文件夹与附件

`@` 引用和附件不同：引用告诉 Agent 使用当前工作区中的文件或文件夹；附件随当前消息上传独立内容。

## 步骤

1. 在 Composer 输入 `@`，从快速索引选择文件或文件夹；键盘上下选择时列表会保持当前定位。选中后显示可删除的文件标签，不把路径写入正文。
2. 引用文件夹时确认它确实是本次任务所需范围，避免给 Agent 无关的大目录。
3. 需要发送工作区外内容、图片或独立文本时使用附件按钮，而不是伪造路径引用。
4. 发送前检查引用标签与附件列表；删除错误项后再发送。

普通工作模式的同一 `@` 列表还可选择当前 Node 和 Workspace 中已登记的主会话，匹配会话排在文件之前，不设置类型切换 Tab；输入 `@session` 或 `@session 关键词` 可只查会话。裸 `@` 显示首批会话，文件搜索需要输入路径；每种来源只显示首批结果，结果过多时请细化关键词。当前会话与子会话不列入候选，托管对话和分享入口不提供普通会话目录。

选择会话与选择文件一样：移除光标处的查询词，显示可删除的会话引用标签，不把标记写入正文。标签保存会话 ID 和选择时的名称，发送时与文件引用统一作为 XML 资源输入交给 Agent，消息回显显示只读引用标签，不显示 XML。相同会话不会重复添加，同名会话按 ID 区分；会话、文件与文件夹引用合计最多 128 项，并随当前工作区草稿恢复。点击标签可以移除；正文为空时按 Backspace 移除最后一个引用。编辑排队消息的正文会保留引用元数据。引用不会导入历史、发送协作消息或自动读取来源会话；是否读取仍由 Agent 及其原有工具和权限决定。

从剪贴板粘贴达到 100 行或 10000 字符的长文本时，Composer 会自动生成 TXT 附件；输入框原有正文保持不变。

普通工作区和托管对话上传 BMP 图片时，浏览器会保持原分辨率转换为 PNG，附件名变为 `.png`，本地原文件不变。源文件及转换结果均不能超过 5 MiB，图片不能超过 1600 万像素；不会自动缩小。转换失败或超限时，请另存为较小的 PNG 后重新添加。PNG、JPEG、GIF、WebP 不受此转换影响。

**成功标志：** Composer 显示文件引用标签或上传附件列表。发送后，`@` 引用以只读小标签回显；图片附件以不带文件名文字或文件名悬停提示的缩略图卡片回显，其他附件以文件类型图标和文件名列出。点击图片直接在弹窗中放大预览，Ctrl/Cmd+Click 可在独立窗口打开；缩略图加载失败时回退为图片占位提示，点击后仍会重新检查附件是否可用。其他文件使用普通文件预览。图片同时作为视觉输入交给支持图片的 Agent，不只是路径引用。

## 引用选中的片段

选区引用与 `@文件` 不同：它把你此刻看到的文字保存为快照，不要求 Agent 重新读取当前文件。

- 在文本文件或 Diff 中选择内容，再从原右键菜单选择**引用**。**全选**只选择当前页已加载的正文，包含滚动范围外的内容；不会读取其他文件、自动引用或发送。移动端从文件底部操作组打开同一菜单。
- 在 Chat 的同一条 Agent 回复正文中选中文字，桌面会在选区上方显示**引用**按钮；选区内右键也可复制或引用。移动端保留系统选字菜单，并从该消息已有操作区的**引用**按钮加入选区。链接、图片及非正文内容不被这个菜单接管。
- 加入后只出现一个可移除的小标签，正文和原有引用保持不变，文件窗口也不会自动关闭。可继续写意见后发送；只有引用、没有正文也能发送。
- 引用发送到来源工作面的草稿；主会话与侧会话不互相投递。菜单打开后切换了目标，请在当前目标重新打开菜单。独立文件窗口不向其他窗口投递引用。
- 未保存编辑、历史版本和生成中的回复保留来源说明；加入后的快照不会随文件或回复变化。每段最多 8,000 字符，所有引用共用 128 项及编码后大小限制；超限请缩小选区或移除引用，不会静默截断。
- 发送后仍只显示只读小标签，不展开片段或 XML。复制该用户消息会保留公开输入中的引用 XML。普通工作区的片段随原 Workspace 草稿恢复；托管和分享入口沿用各自草稿生命周期，不扩大文件权限。

## 附件保留

- 已发送附件按当前会话保留：准备、排队和执行期间不会清理；会话空闲后保留 30 分钟。
- 在期限内继续发送有效消息会暂停清理，再次空闲后重新计时。查看历史、切换会话或打开预览不会延长时间。
- 过期后消息中的文件列表保留，但点击提示“文件已过期”；需要继续使用时请重新上传。Node 正常停止也会清理临时附件，不保证原预览地址在重启后保留；普通 Workspace 的 MAR Agent 在[正常停止交接](sessions.md#正常停止后的自动续作)中会保留尚待发送的附件内容，恢复时重新准备。
- 未发送的已完成上传保留 1 小时，移除附件会提前删除暂存文件。`@` 引用不上传、不复制、不参与附件清理，仍指向工作区中的原文件。

## 失败排查

- 找不到文件：先在当前 Workspace 文件树确认路径；只能引用已授权目录内的内容。
- 附件上传失败：检查浏览器网络和提示，重新选择文件；不要把密钥文件作为附件发送。

安全提示：`@` 引用不是权限提升，附件也不应包含凭据或应提交到 Git 的秘密。

下一步：[浏览、搜索与管理文件](files.md)。

附件保存在 Node 私有数据目录的 `temp-files/`，不会在 Workspace 中创建 `.mar` 或修改 Git 忽略规则。消息中的附件仍可预览和下载，但不能作为 Workspace 文件编辑；预览只在附件保留期间有效。
